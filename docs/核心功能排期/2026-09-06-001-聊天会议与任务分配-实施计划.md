# 聊天、会议与任务分配怎么按顺序交付？

本轮只交付三个真实功能：聊天闭环、开会、独立任务分配；待办是三条流程共用的状态。四类获准上下文是共同基础，不建设企业级 Agent 平台。

> JC 于 2026-09-06 本轮重新收窄范围。执行者先读根 AGENTS.md、harness/规范/001、004。上一份产品规划 013 保留为长期候选，本文件是当前执行入口。排期采用“本轮开发—整体检查—演示前”，不沿用旧比赛截止推算新的演示日期。

## 用户最终怎么用？

| 功能 | 最小闭环 | 本轮完成标准 |
| --- | --- | --- |
| 聊天 | 找同事 → 对方 Agent 查获准上下文并完整答一次 → 找本人 → 原对话聊天 → 结束 → 摘要/待办建议/记忆 | 可不产生任务；只有负责人选择加入才创建待办；重复结束不重复写入 |
| 同步会 | 输入议题和相关成员 → 各个人 Agent 查上下文 → 值班 Agent 汇总 | 输出有来源的同步简报，发起人可继续找人；不要求真人参会 |
| 决策会 | 收集上下文 → 推荐必要参会人 → 发起人选人 → 同一文字会议室 → 结束并整理 | 人决定结论；会后建议由责任人加入自己的待办 |
| 任务分配 | 输入任务 → 各 Agent 收集资料和状态 → 推荐 1–3 人 → 发起人选择 → 对方待办 | 真实推荐、明确依据；分配只向发起人选择的人生效，不伪装为本人主动承诺 |

聊天继续遵循已确认的 Agent 先完整回答规则。不做倒计时弹窗、不强拉真人；会议先做文字会，不包含音视频。

## Agent 从哪里取得上下文？

| 来源 | 首批读取范围 | 权限和更新 |
| --- | --- | --- |
| 个人工作台会话 | 本人明确共享的个人会话内容；本人自己的助手可读本人会话 | 私人默认不对同事开放；只读原始正文，不暴露模型内部思考；撤销后后续读取立即失效 |
| 共享资料 | 当前账号公开给本次对话全部接收者的资料 | 复用资料版本和权限；不因为 Agent 能读取就扩大转述范围 |
| 动态状态 | 获准的待办、优先级和会议状态 | 按实际数据库状态读取；看不到不等于空闲或没有任务 |
| 静态记忆 | 已保存的聊天/会议纪要及手工沉淀 | 保留来源；先进入本人记忆，是否对外共享由本人决定 |

会话、资料和记忆复用当前后端的增量全文索引；按问题检索相关摘录，并在读取、生成和结果展示时复核权限。四源可用不表示每个问题都强行加载全部内容。每次代答通过真实只读工具获取内容。收集失败、没有证据和生成失败都呈现实际状态，不用静态模板冒充模型结果。案例资料可以虚构，但在隔离工作空间中作为真实业务数据运行；不混入现有团队数据。本轮先不自动生成案例人物。

| T4 | 独立任务推荐与分配 | 已完成 | 候选 1–3 人且有依据；用户选择后落入负责人待办；不重复分配 |

顺序串行推进；每项先处理其依赖和测试，再更新状态。完成第一遍后做整体检查；演示前只修阻塞，不增加桌面采集、企业权限、收费或外部 Agent 宿主。

- 本轮不提交或推送 Git、不公开部署；服务更新前检查活跃生成，避免打断现有使用。

## 前端还要重点看什么？

- 聊天：本人和 Agent 身份是否一眼可分；找本人、结束、新事项保持同窗；不出现倒计时弹窗。
- 开会：同步会直接出简报，决策会先选人；会上正常发言不被 Agent 生成锁住，结束入口明确。
- 分配与待办：推荐理由简短；只选一人；任务分配与本人主动加入使用不同来源标记；未确认建议可从待办页进入。
- 资料：会话的团队共享开关、资料共享范围、状态共享开关需要 JC 走查一次；默认私有记忆不会自动泄露。
- 视觉：继续压缩重复导航和模型长回复；内部 ID 不应成为阅读内容。必要时只调整排版与提示词，避免临场改变业务流程。

## 什么情况暂停演示或缩范围？

| 信号 | AI 的处理 | JC 的判断与安全终态 |
| --- | --- | --- |
| 模型失败或长时间等待 | 保留真实失败、手动重试，检查实际调用；不生成假成功 | 先展示已真实完成的记录，现场生成恢复后再继续 |
| 撤权后仍能读取内容、任务归属错误 | 停止受影响路径并修复权限/状态测试 | 不展示存在越权或错误分配的功能 |
| 双端消息不一致或未确认送达 | 核查登录、轮询、网络与数据库 | 不承诺即时送达；验收通过再演示真人闭环 |
| 案例资料缺少依据 | 标记证据不足，不硬凑候选 | 补充案例经历或缩小任务，不用编造推荐填空 |

聊天与会议为站内文字协作；通知以站内列表和待办建议为主，尚未实现离站推送、音视频、桌面文件自动采集、飞书持续同步或多租户切换。自动识别真实会议/专注状态、MCP 通用接入、企业权限与商业化留待三条闭环稳定之后。

## 2026-09-06 会话附件与路演空间

工作台文件采用两段式流转，界面和权限使用同一条规则：

1. 用户可以在本人工作台粘贴、拖入或选择文字文件。文件先作为当前会话的过程附件，AI 在本轮和后续追问中可以继续读取。
2. 过程附件不进入资料列表、工作池或同事 Agent 的检索范围。消息旁显示文件名和“入工作池”，不额外弹窗解释。
3. 用户点击“入工作池”后，系统才创建团队共享成果；重复点击不会重复发布，其他账号不能替附件所有者发布。
4. 首批读取常用文本、Markdown、JSON、CSV、代码与日志文件；一次最多 5 个，总内容最多 64,000 字符。图片和二进制文件尚未进入模型上下文。

左侧已把搜索移到最上方，移除“资料、全部、需要你、课题”四个重复入口；保留工作台、找同事、开会、分配任务和文件夹。右侧工作池删去发布人、日期等常驻小字，聊天正文、文件名、待办标题和导航字号提高一级。

已新增 `tools/prepare-showcase.py`，只允许在独立数据目录创建三账号案例空间，并明确拒绝写入 `.local/workspace`。当前已生成 `.local/showcase`，含 3 个成员、6 份公私资料、3 条个人工作台会话和 4 个待办；凭据只保存在本机权限为 600 的文件中，不同步飞书。案例是可查询的真实数据库状态，现场 Agent 回答仍调用真实模型，不保存预制生成结果。

自动化现为 77 项后端测试通过，既有 HTTP 契约保持不变；前端类型、构建和 UI 边界检查通过。可见浏览器使用隔离账号完成文件选择、发送、真实模型读取和显式发布：模型正确读出附件唯一关键词，工作池共享成果从 4 项增加到 5 项。截图保存在本地 `screenshots/2026-09-06-工作台待办与工作池/03-会话附件与工作池-1440.png`。

## 2026-09-06 本地 Codex 发布成品

私人工作台内容不自动进入共享区。工作池只接收用户明确发布的成品，入口收敛为两种：

1. 网页右侧直接拖入或选择成品，文件名作为标题并发布到团队工作池。
2. 用户在本地 Codex 明确要求共享某个成果后，由 Codex 运行 `tools/accord_share.py publish <文件>`，通过 Accord API 放入团队工作池。

右侧已移除“共享 / 自己”切换和标题、正文、组合资料、发布范围组成的新建表单，只保留待办、拖入成品、搜索和团队成品列表。过程文件仍可先放在个人会话中，只有消息旁点击“入工作池”或通过上述两个入口发布后，其他成员 Agent 才能读取。

CLI 首次使用登录一次，只在权限为 600 的本机会话文件中保存七天会话，不保存密码；支持列出近期可选文本文件、查看当前工作空间、发布指定文件和退出。它不会读取私人聊天，也不会默认上传目录。相同账号对相同路径和内容重复执行发布命令时复用同一操作结果。

隔离账号已经实际完成本地 CLI 登录、发布和跨成员读取，另一成员能够看到新成品；重复执行两次只新增一项。网页可见浏览器完成文件选择，工作池从 5 项增加到 6 项，旧表单和范围切换均未出现。当前 80 项后端测试、前端类型检查、构建、UI 边界检查和 CLI Ruff 检查通过。截图保存在本地 `screenshots/2026-09-06-工作台待办与工作池/04-精简工作池与拖入成品-1440.png`。
