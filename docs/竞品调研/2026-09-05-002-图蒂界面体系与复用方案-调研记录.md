# Tutti 界面体系与 Accord 复用方案

> 来源：[Tutti 仓库](https://github.com/tutti-os/tutti/tree/404a084f7780c475212f80d6563964c4bd7d8324)，检查日期：2026-09-05，固定 commit：`404a084f7780c475212f80d6563964c4bd7d8324`。结合源码、设计规范及本地 Tutti Dev 暗色工作台观察。数值来自源码定义，未逐项测量运行时 computed styles；插图是仓库随附的公开宣传示意图，可能与当前版本不同。

## 0. 结论

Tutti 的桌面界面采用 **React 19 + TypeScript + Tailwind CSS 4**，Electron 承载桌面窗口，Vite 负责前端开发和构建。它在 shadcn/Radix 基础上维护了自己的 **`@tutti-os/ui-system`**，把颜色、字体、间距、基础组件、图标与组件使用规则收在一起。

它的协调感主要来自一致的工作台视觉规则：中性色大面积铺底，细边框区分层次，紧凑但规律的排版，少量强调色提示状态。启动页和空状态允许插画、特殊字体；进入工作区后，视觉重点回到内容与操作。

**Accord 可以先借用视觉规则，之后再决定是否接入 React 组件库。** 当前 MVP 是 FastAPI / SQLite / 原生 JavaScript；迁移颜色变量和组件样式不要求同时改写业务前端。本文是调研建议，尚未成为 Accord 的强制设计规范，也未修改产品界面。

## 1. 技术与规范分别是什么

| 层次 | Tutti 的实现 | 对 Accord 的意义 |
| --- | --- | --- |
| 桌面容器 | Electron 43，electron-vite | 提供桌面窗口与系统能力；视觉风格可以在 Web 实现 |
| 前端框架 | React 19、TypeScript、Vite 6 | 直接使用其 React 组件时需要匹配依赖 |
| 样式 | Tailwind CSS 4、CSS Variables、语义颜色 | 可将关键变量和规则翻译到现有 CSS |
| 基础组件 | 自有 UI System；shadcn 配置为 `radix-nova`，中性底色；Radix、DiceUI 等 | 组件交互有基础能力，视觉经过项目自身调整 |
| 图标 | shadcn 配置使用 Lucide，UI 包统一导出图标，也含自定义 SVG | Accord 应统一尺寸、线条和导入入口 |
| 动效 | CSS / tw-animate-css；Agent GUI 使用 Framer Motion | 小反馈短而稳定，避免 hover 引起布局跳动 |
| 组件展示 | `apps/ui-storyboard`，自建 React/Vite 展示应用 | 集中查看字体、颜色、尺寸和组件状态；项目名为 Storyboard，并非 Storybook |
| 维护规则 | 组件 metadata、稳定导出、依赖边界检查、生成 token 检查 | 让多个页面持续使用同一套设计规则 |

这里的“标准”主要指 **Tutti 自己的产品设计系统与工程约定**。已读材料没有将它声明为 Apple HIG、Material Design 或某项无障碍认证；Radix 提供交互基础也不等于整个应用已通过无障碍验收。

## 2. 可以提取的样式规则

以下区分源码值与 Accord 建议。尺寸适用于桌面 Web UI；`renderer-theme.json` 同时包含 Native 参数，不能把其中的移动端控件尺寸当成桌面标准。

| 项目 | Tutti 的规则或源码值 | 视觉作用 | Accord 建议 |
| --- | --- | --- | --- |
| 间距 | Storyboard 的 4px 网格：4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 | 列表、工具栏、面板形成稳定节奏 | 首版收敛到 4 / 8 / 12 / 16 / 24 / 32 |
| 普通按钮、输入框 | 默认高度 32px，圆角 6px；按钮文字 13px | 紧凑、精确，适合工作台 | 桌面沿用；触屏尺寸单独评估 |
| 圆角层次 | 展示规范建议：控件 6px、大控件 8px、卡片/菜单 12px、大弹窗 16px | 通过形状区分组件角色 | 固定角色映射，避免每个卡片独立选圆角 |
| 常规字号 | 标题 24px，窗口/弹窗标题 15px，正文/控件 13px，辅助文字 11px | 层级细腻，页面不显拥挤 | 中文长消息可试 14px，密集导航维持 13px |
| 字重 | 正文 400，中文强调优先 500；部分英文标题规范为 600 | 避免中文大面积粗黑 | 为正文、标题、状态分别设置角色 |
| 字体 | 英文 Lexend；中文 locale 优先 PingFang SC、微软雅黑、Noto Sans CJK SC 等，混排随 CJK 字体栈 | 中英文、数字的观感一致 | 中文优先系统字体；不要强制中文使用英文字体 |
| 亮色会话区 / 侧面板 | `#FCFDFF` / `#F4F5F7` | 相近明度形成结构 | 先确定内容区、导航区、浮层三种表面 |
| 暗色会话区 / 侧面板 | `#181818` / `#2A2A2B` | 主内容与辅助面板自然分层 | 可以作为暗色候选，不必绑定为品牌色 |
| 强调色 | Web 亮色 `#4182F5`；暗色 `#5A9BFF` | 焦点与少数状态突出 | 颜色按“焦点、成功、失败、待确认”定义用途 |
| 主按钮 | 基础 default variant 使用主文字色作背景、反色文字 | 真正推进流程的动作更清晰 | 每一区域只突出最关键动作，如“确认分配” |
| 边框与深度 | 低透明度边框、轻微表面变化、少量阴影 | 面板有边界，视觉噪声低 | 少嵌套卡片，用间距与分隔线分组 |
| 图标 | 常规窗口工具图标 14px，身份图标 20px；基础按钮也有 16px 图标规则 | 图标融入文字和工具栏 | 按场景固定尺寸，保持对齐 |
| 动效 | hover/color 建议 120–200ms；CSS 弹窗打开 250ms、关闭 150ms | 反馈明确、节奏平稳 | 优先颜色/透明度反馈，保留减少动态效果支持 |

圆角展示规范和 CSS 通用别名并非完全相同：例如 CSS 的基础 `--radius` 为 10px，别名推导出 4 / 6 / 10 / 14 等值。复用时要明确采用哪一组，不应把展示建议当作每个现有组件的实际尺寸。

本地暗色空状态还观察到：大面积留白、居中输入区、小型插画，以及局部衬线斜体的 Provider 名称。对应样式使用 Merriweather / Georgia。这个装饰只用于少量空状态，不适合扩散到任务列表和中文正文。

## 3. 上下文引用与列表层次

![Tutti 上下文引用宣传示意图](../../screenshots/2026-09-05-图蒂界面拆解/01-上下文引用-仓库示意-1600x1000.jpg)

原图：[仓库 at-history.jpg](https://github.com/tutti-os/tutti/blob/404a084f7780c475212f80d6563964c4bd7d8324/docs/assets/zh/at-history.jpg)。此图包含演示性叠加面板和背景，不能用于测量当前窗口布局。

**观察：** 图标、主标题、次级说明、右侧元信息有固定位置；选中项只改变局部底色。大量信息借助对齐和分组保持可扫描性，用户能够先读名称，再决定是否查看细节。

**前端知识点：** 列表行可用 Grid/Flex 固定图标和操作位置；长标题单行截断、说明降低对比度；hover、selected、keyboard focus 分别定义。弹层需要处理越界、Escape 关闭和键盘导航，视觉相似不能替代这些交互。

**给前端 AI 的描述模板：**

```text
为 Accord 设计上下文选择列表。每行按“类型图标、标题、来源说明、右侧元信息”对齐，使用 4px 间距网格、安静的中性色表面和细边框。选中态采用轻量底色，键盘焦点另有清晰标记。支持长中文标题、空结果和加载状态。保留可见范围和来源信息，使用 Accord 自己的内容与图标资产。
```

**Accord 怎么借：** 用于找同事、选择共享成果、引用会议结论。成员行明确标注当前进入“某某的 Agent”还是“找本人”；资料行保留来源与共享范围，避免用户误认为所有检索到的材料都能转发。

## 4. 待处理面板与行动卡片

![Tutti 待处理面板宣传示意图](../../screenshots/2026-09-05-图蒂界面拆解/02-待处理面板-仓库示意-1600x1000.jpg)

原图：[仓库 control-center.jpg](https://github.com/tutti-os/tutti/blob/404a084f7780c475212f80d6563964c4bd7d8324/docs/assets/zh/control-center.jpg)。图中的审批、运行与完成分组是公开示意，不代表本轮已经执行并验证这些流程。

**观察：** 状态先分组，再显示具体事项；等待用户处理的卡片拥有清楚的操作区，运行中和已完成事项更轻。紫色淡底与白色内层使待处理内容得到有限强调。

**前端知识点：** 状态应映射到稳定的组件变体；标题、来源、摘要、动作分区。不要只靠颜色传达状态，应同时提供文字。卡片状态来自后端数据，点击后的处理中、失败、已确认反馈必须清楚。

**给前端 AI 的描述模板：**

```text
为 Accord 设计“待我拍板”面板。优先显示待本人决定的事项，依次说明谁发起、需要决定什么、Agent 已整理的依据，以及明确的确认操作。运行中和已完成事项使用更轻的列表。保持中性色表面、小圆角、细边框和稳定的按钮位置；待确认、处理中、失败和已确认都显示文字状态。
```

**Accord 怎么借：** 聚合任务分配确认、找本人请求和会议结论确认。卡片视觉可以共用，按钮和确认后果必须按业务区分；“确认会议结论”与“加入我的待办”仍是分别发生的动作。

两张图片是仅用于研究的本地附件，沿用原始 JPG 格式，受 `screenshots/` 忽略规则保护；其他协作者拉取仓库后可通过上述原图链接查看。它们不作为 Accord 产品资产。

## 5. 两种复用路径

### A. 当前比赛版本：先采用视觉规则

在现有前端中定义 Accord 自己的颜色、字体、间距、圆角变量，先统一按钮、输入框、列表行、状态标签和面板，再应用到个人工作台、找同事和待我拍板。保留已有业务接口与确认流程。

建议先做一个隔离的工作台预览，包含默认、hover、焦点、禁用、加载、失败、空状态、长中文内容；确认可读性与状态表达后，再逐页应用。以上是下一步建议，本轮未创建预览或改写产品。

### B. 后续 React 前端：评估直接接入 UI System

`npm view @tutti-os/ui-system version peerDependencies --json` 于本次检查返回已发布版本 **0.0.427**，React / React DOM peer 为 `^19.1.0`。固定源码 commit 的包版本为 `0.1.0`；不能假定 npm 最新包与本地源码完全一致。

官方包 README 支持外部安装、导入 `@tutti-os/ui-system/styles.css`，并说明 Tailwind 扫描包产物的配置。正式采用前应锁定具体版本，用一个页面验证组件、样式、中文和主题；本轮只核验包信息，未安装到 Accord，也未完成独立接入验收。

采用 React 组件库不要求照搬 Tutti 的 Electron 桌面容器、Go 后端或业务状态管理。共享 UI 包自身要求与宿主解耦，具体应用仍负责数据、权限和业务操作。若引入第三方代码，记录来源并保留适用的 LICENSE / NOTICE。
