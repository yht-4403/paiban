# 会话拖放与模块化上下文

> 2026-09-05。来源：JC 关于拖动授权、跨文件夹移动聊天、切换与组合上下文、AI 自主调用读取工具的需求；当前 Accord 源码及官方 Function Calling 文档。本文保留实施前设计，首批执行结果见文末本轮交付状态。参考 Codex 的组织方式，不据此宣称 Codex 的文件夹、记忆或权限具有相同机制。

## 核心体验

用户通过位置和对象操作组织工作：把聊天移入文件夹，把资料拖入当前会话，把待分享内容交给明确的人。界面保持三个可辨认的落点：侧栏文件夹、当前资料区、参与者区域。沿用 Tutti 的列表、面板、图标和反馈；常规成功以对象实际变化表达，不持续展示教程或弹出确认框。

面向在个人探索与团队协作间切换的成员，目标是复用已有资料、减少复制粘贴、清楚当前 AI 能看什么。该画像来自 JC 需求，属于假设型。当前会话没有文件夹，资料每次通过选择器引用；后端按文本匹配取共享资料，尚无模块绑定或模型工具循环。主要摩擦是重复选资料、跨会话搬上下文、共享与归档混在一起。

本设计将操作语义分清，但不要求用户学习后端权限模型。图标用于辅助识别；“仅自己”“资料”“分享”等短标签保留，操作结果和接收者始终可见。详细说明留在出错或主动查看详情时。

## 与异步协作工作线的结合

2026-09-05，结合 JC 引用的《黑客松：竞品技术架构拆解》及 [007 实施计划](2026-09-05-007-独立探索与集中收束工作流-实施计划.md)，将后续开发组织为两条工作线，共用一个工作台。

| 工作线 | 负责的用户行为 | 交付边界 |
| --- | --- | --- |
| A：异步协作 | Agent 先代答、补齐信息，需要本人时交接，承接后持续推进；课题支持独立探索、提交、统一公开、比较与决策 | 定义工作阶段、责任人、提交版本、公开时点和下一步；日常协作不强制创建课题 |
| B：工作区与上下文 | 用文件夹整理会话，拖入资料供 AI 查阅，在参与者区域准备分享或交接 | 定义整理位置、资料绑定、当前受众与直接操作；参与者区域承接 A 的业务动作 |

[多人多 Agent 架构](../技术架构/2026-09-05-001-多人多智能体协作架构-设计文档.md)为两条工作线提供共同的身份、授权、执行和持久状态能力。每人的多个 Agent 在内部按能力分工，对同事仍保持一个简单入口；不要求用户为每个内部 Agent 配一套文件夹或学习调度流程。

界面沿用同一工作区：左侧文件夹与工作列表，中间聊天和当前工作，资料区展示可用来源，参与者区域展示与当前工作有关的人及已获准公开的状态。“需要你”“进行中”等作为同一工作列表的筛选；课题中的探索、比较、决策是主内容区随阶段展开的工作视图。007 中的六个关键界面描述六种工作状态，提交、公开和决策表单就地展开，不据此增加六个常驻入口或连续弹窗。

一条贯通路径是：共同简报固定为本轮资料 → 各成员用自己的聊天独立探索，并附加获准资料 → 整理成果，点击“提交本轮”保存快照 → 主持人统一公开 → 已公开方案成为比较可用的资料 → 确认决策与交接内容 → 接收者明确承接后继续工作。聊天、资料引用和任务保持关联，不必复制私人聊天到共享文件夹。提交本轮与直接发给某人是不同落点；不能借普通分享入口提前公开受本轮规则保护的方案。

两条工作线必须采用以下共同契约：

- 会话保持稳定 ID，并独立记录个人归档位置、工作用途、课题轮次及可见范围。移动文件夹不改变探索阶段或访问权；探索会话跨文件夹移动后，本轮共同简报仍保留固定版本，文件夹默认资料只作为经范围检查的补充。
- 后端共用一个上下文构建与鉴权入口。007 的 `accord_thread_scopes` / `accord_run_inputs` 与本设计的 `RunContextManifest` 表达同一套用途和运行输入记录；实现时统一字段与存储，不各建一套。记录资料版本、消息截止点、绑定来源、目的与回答受众；模型工具读取和普通发送、搜索、重试都经过同一范围检查。
- 挂载资料表示在有效权限内可供本次工作读取，不等于向参与者公开。个人资料可支持私人探索；提交正文和引用要单独核对分享权。受众变化时重新构建获准上下文，不能把私人会话、缓存或尚未公开的方案带入对外回答。
- 参与者区域复用同一个工作卡和状态记录。拖入某人的头像或内容可以准备接收者与待发对象；只有明确发送、公开或接受动作才改变对应业务状态。已读、Agent 正在生成和本人已承接分别记录，不从头像出现推断授权，也不从 Agent 忙碌推断本人正在工作。
- 提交、公开、分享、承接、完成各有幂等命令和服务端状态校验；前端菜单、拖动和通知都调用这些命令，通知返回原工作。主持人管理轮次，不自动读取私人探索；原有分享接口也不能绕过本轮公开规则。

实施先对齐共同的会话范围、资料版本、运行输入和状态契约，再分别接入课题流程与文件夹 / 资料交互。第一次联合验收使用真实账号和模型，完成“两人各自探索 → 提交并统一公开 → 基于获准资料比较 → 确认并承接下一步”，同时证明文件夹移动不扩权、模型真实查阅来源、第三人无法获取私人或未公开内容。会议自动识别、主动预约、多 Runner 和完整多 Agent 调度作为后续扩展，不是这条首个闭环的前置依赖。本节为整合后的实施安排，未新增应用功能。

## 拖到哪里就做什么

| 拖动对象与落点 | 松手后的结果 | 可见反馈 |
| --- | --- | --- |
| 聊天 → 我的文件夹 | 移动原聊天的归档位置，保留 ID、消息、任务关联和访问权限 | 目标展开、该行就位；可撤销 |
| 文件 / 资料模块 → 当前资料区 | 加入这段会话可用的资料，持续到本人移除；默认只读 | 出现带来源图标的资料标签；重复拖入不重复添加 |
| 资料模块 → 文件夹的资料入口 | 设为该文件夹的默认资料 | 文件夹出现资料标记；已有会话按版本规则在后续请求使用 |
| 文件夹 → 当前资料区 | 引用该文件夹已配置的资料集合 | 出现文件夹资料标签；不自动包括目录下所有聊天 |
| 可分享成果 → 参与者区域 | 形成与具体接收者绑定的待发对象 | 在原位置显示内容与接收者；点击发送完成分享 |
| 私人聊天 → 参与者区域 | 整理为待分享工作卡，私人聊天保留 | 就地显示摘要、产物和接收者；全文作为可选内容，不默认勾选 |
| 当前资料标签 → 移除 | 解除本会话的资料绑定 | 标签消失；不删除源文件或模块 |

拖动中使用目标高亮、插入线、对象缩略和短动作标签，如“移动”“加入资料”“分享给…”。分享落点与文件夹落点在空间上分开；不能把一个普通文件夹行同时当作归档与公开所有历史的入口。拖动开始时不改变数据，Esc 或移出合法区域后取消。

聊天属于“我的会话”目录，即使目录名称对应团队项目，移动也只改变本人的归档。已共享讨论仍有原参与者标记；其他成员自己的归档不会随之移动。跨账号、跨团队转移所有权不作为普通移动实现。团队讨论入口处理共享，不把个人文件夹位置当作访问权限。

分享保留一次明确发送动作，但不用模态弹窗：落点直接成为待发卡，接收者头像、摘要 / 附件选择和发送按钮就在卡内。取消拖放后的待发卡不产生通知或授权。已在同一受众内的资料引用与排序直接完成，不重复请求确认。无分享权的附件显示锁定且不可加入；申请权限必须由本人点击发起。

所有拖动都有同等可用的菜单操作：移动到、加入资料、发送给、移除。键盘与触屏不依赖精准拖放或悬停；焦点随移动对象保持，失败回到原位置并给出可重试动作。多人修改通过版本冲突处理，不用后到操作静默覆盖。

## 文件夹与资料模块

文件夹整理聊天，也可以配置默认资料。资料模块是可复用的引用集合，界面统一称“资料”，以名称和图标表现，例如项目背景、UI 规范、用户研究。模块内容可由文档、已发布成果、本人明确选取的会话片段或经批准的摘要组成；原始私人历史不因处于同一文件夹而自动加入。

当前资料区放在会话输入区上方或相邻面板，以紧凑标签呈现。默认继承文件夹资料，也能临时加入其他模块。标签区分文件夹默认来源与本会话加入的来源；点开查看实际文件和版本。移除一个默认资料标签只影响当前会话，恢复入口位于资料列表，不改整个文件夹。

一份模块可以被多个文件夹或工作区引用，更新来源也能复用；绑定动作不复制所有文件或自动迁移目录。已有版本不可静默改写，新请求使用最新获准发布版本，单次运行使用固定版本。同名资料保留来源，矛盾规范不由拖动顺序决定权威；当前项目已采用的规范仍是基线。

首次只支持 Accord 内部登记且有权限的资源，不将文件夹路径直接交给模型读取整台电脑。以后接入本地目录或飞书连接器时，再增加明确的根目录、资源范围与版本适配；凭据、数据库和未发布私人资料不随模块打包。

## 切换与运行时机

| 操作 | 对后续上下文的影响 |
| --- | --- |
| 仅选中另一个文件夹 | 切换浏览位置，恢复该处选中的会话；不会修改后台运行任务 |
| 在某文件夹新建聊天 | 使用该文件夹默认资料，私人历史从空白开始 |
| 把现有聊天从 A 移到 B | 保留历史；后续请求采用 B 的默认资料，本会话明确附加的模块保留，A 的默认绑定退出 |
| 闲置时添加 / 移除模块 | 下一次发送即使用新的资料集合 |
| 排队或生成中修改资料 | 界面以“下次使用”标明待生效变化，当前运行保留启动时的资料版本；可停止后使用新资料发起下一次请求 |
| 撤销资源权限或移出成员 | 权限立即失效，阻断后续读取与发布；固定版本不能绕过最新授权检查 |

移动前的拖动预览可直接显示目标文件夹资料标签，松手后资料区更新。运行中没有静默重启或额外计费；待生效变化与本轮正在使用的资料可以在标签详情查看。

移除资料不等于让模型忘掉已经出现在聊天里的内容。原消息、回答和其中引用可能保留先前信息。需要独立思考时用“以这些资料新建聊天”，默认不带旧历史；可由本人另选允许带入的目标或摘要。向新的接收者回答时必须构建新的授权上下文，不能直接续用含私人材料的模型会话、摘要或缓存。

## AI 自主查阅的边界

加入模块表示授予本次工作在有效权限内查阅它的范围，不等于立即把全部正文塞进提示词。模型先得到当前有效资料的精简目录，再按问题调用只读工具，逐步取得需要的内容。

| 工具 | 提供什么 | 服务端控制 |
| --- | --- | --- |
| context_list | 已绑定且对当前回答受众可用的模块与资源目录 | 不列出未授权对象、私有标题或隐藏计数 |
| context_search | 在有效模块内检索相关片段 | 先鉴权再检索；限定结果数量、片段长度和版本 |
| context_read | 读取指定资源与范围 | 使用登记 ID，逐次复核权限；不接受任意系统路径或外部 URL |

选择哪个文件、检索什么词、需要读哪些段落可以由 AI 决定，不为每次获准读取弹窗。没有找到资料时直接反馈缺项；不能悄悄回退到整个团队、其他文件夹或用户其他项目搜索。

真正的执行链路是：服务端建立本轮资料清单 → 模型提出工具调用 → Accord 校验参数与权限后执行 → 将结果连同来源交回模型 → 模型继续查阅或回答。千问官方 OpenAI 兼容接口文档提供 tools、tool_calls 及应用执行函数后回传结果的流程；该协议可以支撑本设计，但当前配置模型的实际工具返回和流式兼容性仍需专门验证。[官方 Function Calling 文档](https://help.aliyun.com/zh/model-studio/qwen-function-calling)

界面只显示与工作有关的反馈，例如“正在查阅 UI 规范”；点开可以看到实际读取的来源与步骤。最终引用必须能对应真实返回的资源版本。不要显示虚构工具轨迹，也不把模块已绑定写成该模块所有文件都已读过。

有效读取范围同时受到调用者身份、工作委托、已绑定模块、源资源权限与回答接收者约束。工具参数不能自称管理员、扩大接收者或更改授权。资料正文与检索结果是参考内容，不能改变工具权限和系统规则。私有模块可用于本人的私人工作；不因本人能读就允许向团队回答其中内容。

首批工具只读；发送给同事、修改文件、删除、执行 shell 和修改权限属于独立动作，不随拖入资料一并开放。修改建议可以出现在工作卡中，再通过已有的本人确认流程执行。

## 现有代码需要补什么

当前 agent.py 不传 tools，也不处理 tool_calls；它把匹配的共享文本和会话历史直接交给模型。runtime.py 从共享 artifacts 取资料，前端引用在发送后清空。因而文件夹、持续模块绑定、版本快照、细粒度资源读取和工具循环都属于新增能力。

| 后端对象或改动 | 具体作用 |
| --- | --- |
| Folder 与 ConversationPlacement | 保存个人目录、排序和会话位置，移动保留会话 ID；归档权限与读取权限独立 |
| ContextModuleVersion | 保存模块名称、来源、发布版本与明确资源引用；不直接暴露任意本机目录 |
| ContextBinding | 记录文件夹默认、本会话附加与排除项，持久化当前资料选择 |
| RunContextManifest | 在请求受理时记录模块、资源版本、工作目的与受众，运行时再核验最新权限 |
| 只读工具入口与 ToolCallRecord | 校验 schema、身份和范围；记录实际读取、状态、来源及错误，不把私人正文复制到通用日志 |
| 模型工具循环 | 完整接收并校验工具参数后执行，正确关联 tool_call_id；分轮保存用量、停止和失败状态 |

移动、绑定和分享分别提交幂等命令，并校验目标版本。共享资料需要先补服务端范围过滤；不能把私人模块写入当前全员可见的 artifacts 集合，再只在 UI 上隐藏。检索索引、结果缓存、引用、导出与通知沿用相同范围，撤权使相应缓存失效。

工具循环设置服务器侧的轮数、读取量、时长和费用边界。一次工作可能产生多次模型请求，实际用量按所有调用累计，取消或失败不能抹去已发生的消耗。重新生成不会自动重复已完成的外部写操作；本批只读工具也要防止无限循环和重复加载同一片段。

## 实施顺序与验收

先落实上节两条工作线的共同契约；以下是工作线 B 内的实施顺序。第一步完成个人文件夹、聊天移动、稳定 ID、撤销和键盘等价操作。第二步加入资料模块、持续绑定、文件夹默认与运行快照，界面只显示真正可用的资料。第三步打通真实的只读工具循环，验证检索、权限、来源和费用。最后将分享落点接入工作卡与授权，沿用 [008 的同一工作台](2026-09-05-008-团队工作状态与可见权限-设计文档.md)；[007 的独立探索](2026-09-05-007-独立探索与集中收束工作流-设计文档.md) 仍在合法公开前保留私人过程。

以下均为待执行验收，不代表功能已上线：

1. 移动聊天后刷新，消息、任务和 ID 不变，原参与者之外的人无法从目标文件夹、搜索或计数得知内容；失败恢复原位置。
2. 拖入、重复拖入、移除和恢复资料均得到正确绑定；文件夹默认变更不覆盖本会话明确选择，不删除源资源。
3. A 移到 B 后，新请求采用 B 的默认资料且保留明确附加项；旧请求保持自己的版本；撤权仍立即阻止后续访问。
4. 点击新建聊天可得到无旧历史的上下文；直接移动聊天不会被描述成已经清除旧上下文。
5. 模型能实际调用目录、搜索和片段读取，回答引用与工具结果对应；没有模块时不读取全局资料。
6. 第三人、其他团队、非法资源 ID、伪造路径、资料内恶意指令和过期授权不能越权；对外回答不继承私人推理缓存。
7. 私人聊天拖到参与者区域仅产生待发卡；点击发送前没有授权、消息或通知。已共享资料的同范围引用不出现重复确认。
8. 工具超时、部分结果、流式参数未完成、停止、重启、重复请求与读取量超限均有真实状态；费用按实际调用累计。
