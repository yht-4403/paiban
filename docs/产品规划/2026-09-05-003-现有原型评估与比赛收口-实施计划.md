## 首版要证明的价值

**团队成员先问同事的 Agent，需要本人决定时再明确找人；最终责任和已确认事实始终可追溯。**

“多人 + 多 Agent”本身不足以区分 Tutti VM。Accord 应展示一次完整协作请求中，哪些问题 Agent 已接住、哪些决定必须交还给谁、何时打断以及依据是什么。用实际演示呈现这些行为，不能把尚未建立的数据隔离写成已完成优势。

## 演示脚本：先按 3 分钟制作，可按赛制调整

1. 0:00–0:20：A 需要产品口径，B 正在开发；展示一个会打断工作的真实类型问题。
2. 0:20–1:00：A 问 B 的 Agent，基于已共享资料回答并显示来源；B 的界面没有新增真人待处理事项。
3. 1:00–1:40：A 提出需要 B 决定的问题，Agent 明确拿不准；A 点“找本人”，选择紧急程度，看到准确的送达时间。
4. 1:40–2:20：B 接手，给出结论；明确确认后记录到记忆或创建有负责人的待办。
5. 2:20–3:00：展示请求、依据、确认人和结果；快速证明私人草稿没有进入他人快照，任务不会因无关聊天完成。

会议的完整撮合、多文件编辑和更多接入放到备选演示，避免主线变成功能巡游。录屏作为恢复方案；回放和无 Key 降级必须标注，不能冒充实时模型调用。
