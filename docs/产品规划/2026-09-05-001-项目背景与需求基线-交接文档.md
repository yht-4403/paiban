## 二、产品要解决什么

团队沟通里，查材料、问进度、约人、分配任务和同步状态常常直接打断真人。Accord 让这些请求先经过成员各自的 Agent，利用可共享的资料完成代答和信息整理，把判断、承诺与执行放行留给人。

云端说明面向一般办公团队；团队 2026-09-02 的产品方案把首批用户收窄到约 2～15 人、已经依赖 AI 工作的小队，包括黑客松临时团队、项目制工作室和超级个体组成的团队。**建议用参赛团队自己的真实协作验证首版**，此处是基于现有方案的实施建议。

## 三、主要角色与信息边界

| 对象 | 职责或含义 | 关键边界 |
| --- | --- | --- |
| 人机单元 | 一个成员与其专属 Agent、个人工作台、记忆、待办 | 成员决定授权与放行 |
| 专属 Agent | 替成员接收问题、整理上下文、建议协作 | 对方可获知的信息必须经过可见范围判断 |
| 项目值班 Agent | 查看共享状态、收集同步、形成决策简报 | 项目角色不能自然获得所有个人原文 |
| 过程附件 scratch | 某轮工作台对话中的过程文件 | 上传不等于发布，不自动进入共享池 |
| 工作池 | 成员明确发布的成果与共享材料 | 记录发布者、来源和可见范围 |
| 任务/待办 | 工作责任与后续动作 | 建议与已确认分配是不同状态 |
| 决策/会议 | 会前证据、选项、发言、结论与行动项 | 草稿与已确认结论是不同状态 |

## 四、现有 v0 PRD 的具体流程

以下是团队资料中的需求基线，作为 Accord 后续范围讨论的输入，尚非本仓库的已实现功能。

### 1. 进房间与个人工作台

- 一台电脑开房间，另一台浏览器进入，两个名字对应两个单元。
- 默认工作区是自己的工作台；待办和工作池在侧栏。
- 工作台助手结合本人的对话、记忆、待办、共享材料与本轮附件回答。
- 粘贴附件只进入本轮过程；明确“入工作池”后才成为共享成果。
- 现有资料包含按名字续席的 Demo 交互；它不构成可对外部署的身份认证方案。

### 2. 找同事

- 默认消息只进入对方 Agent 通道，对方本人不被提醒。
- 回答不够时，由发送方点“找人”。v0 资料明确要求升级由人发起。
- 找人区分紧急与按截止时间处理的非紧急请求；勿扰影响非紧急打断。
- 验收需要分别看发送者、对方 Agent 和对方真人的可见内容，不能只检查弹窗是否隐藏。

### 3. 任务与异步推进

- Agent 根据经验、相关产出、当前工作台与负载，给出候选人及理由。
- 点“派给谁”后才设置负责人；未确认任务处于待拍板状态。
- 工作台记下待办不等于授权自动派给其他人。
- 完成待办时由 Agent 整理工作进展；资料中“没有进展就问一句、下一句即勾掉”的逻辑需要在实现评审时进一步明确，避免把无关回复误判为完成。

### 4. 同步与决策会议

- 进度同步先向各人 Agent 收集，生成同步摘要。
- 决策会先形成证据、选项与建议参会名单；由人调整名单并召开。
- 进行中的会议需要在刷新、离开大厅再返回后保留。
- 结束会议后先展示结论草稿；人决定是否写入记忆。
- 会后待办逐项确认归属、内容和提醒时间。

## 七、建议的第一条验证路径

两名成员进入同一项目 → A 问 B 的 Agent → Agent 引用已共享材料回答，B 不被打扰 → 遇到需 B 决定的问题，由 A 发起找人 → B 确认后产生任务或结论 → 双方看到正确且一致的共享状态。

这条路径能同时检验代答、共享边界、人工决定和多人状态同步。会议场景随后扩展；具体范围需结合赛期与现有 Demo 情况裁剪。

建议记录：成功由 Agent 解决且未升级的请求数、错误答案数、人工升级次数、同步摘要替代会议的次数、决策会建议减少的参会人数。数量必须关联真实事件，不能使用文案示例填数。

## 八、进入实现前需要补齐

- 比赛名称、截止时间、演示时长、允许复用的范围及提交物要求。
- 采用现有 Demo 继续迭代，还是建立新实现；最终前后端技术栈。
- 首版独立网页或飞书入口，以及期望局域网、云端或其他部署形态。
- 两位参赛成员的测试身份、共享资料样例与明确的授权范围。
- 模型服务和预算；材料中的 API 能力是否实际可用。
