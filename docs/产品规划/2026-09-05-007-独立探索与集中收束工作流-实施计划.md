# 独立探索与集中收束工作流实施计划

> 2026-09-05。JC 要求对照现有代码梳理修改方式和前端 UI 交互。本文是文件级实施方案，未修改应用功能、未创建真实课题或发出通知。延续[同主题设计](2026-09-05-007-独立探索与集中收束工作流-设计文档.md)；默认发散期只看进度，方案统一公开，可见模式尚未收到 JC 的最终选择。

## 结论与实施边界

在现有工作台增加“探索课题”入口，业务集中放到 `features/topics` 和后端 `topics` 模块。复用账号、模型运行队列、聊天基础组件和 Tutti 样式。首先打通课题 → 独立探索 → 提交快照 → 集体公开 → 比较决策，再增加拖动快捷操作。

第一版保留当前 React / TypeScript / Vite / Tailwind / Tutti UI、FastAPI / SQLite / httpx 与 HTTP 轮询。不增加流程编辑器或新的状态管理框架，不把已有找同事的会话状态改造成探索轮次状态。

当前 README 和 006 验收已更新为真实账号与千问调用版本；早期 004 的合成成员不是实施基线。本轮阅读了当前代码和记录，没有重新执行 006 的运行验收。

## 用户与页面目标

沿用 About Face 4 的假设型画像：主要用户是在同一课题下与 Agent 独立探索的成员；次要用户是组织收束的主持人。成员希望放心研究并准确提交成果；主持人希望获得可比较的方案并形成下一步。不能让参与者先理解 Agent 路由、上下文清单和数据库权限才能使用。

成员的主路径是“进入课题 → 继续我的探索 → 整理方案 → 提交 → 公开后比较”；主持人的主路径是“发起 → 看进度 → 公开方案 → 确认决策”。两者共用课题页面，按钮按角色和阶段出现，避免复制成两套产品。

默认保留共同题目、约束和评估维度；不向其他成员提供私人会话、草稿标题或正文。主持人只因主持身份获得轮次管理权，不自动获得未公开内容读取权。

## 前端信息架构与路由

按 JC 后续降低使用心智的要求，与 [010 的两条工作线整合安排](2026-09-05-010-会话拖放与模块化上下文-设计文档.md) 对齐：左侧承载文件夹和同一工作列表，待处理、进行中和课题通过筛选进入。打开课题后，在主内容区按阶段提供概览、我的探索、方案比较、决策；只有有用的视图才展开。下文六个关键界面是工作状态与组件边界，不新增六个常驻菜单；提交、公开、决策使用就地表单，参与者和资料沿用同一工作区。已有入口在迁移中保留可达性，路由表示可恢复的定位，不要求侧栏出现同名菜单。

建议 Hash 路由：

```text
#topics                                      课题列表
#topics/<topicId>/<roundId>/overview           简报与进度
#topics/<topicId>/<roundId>/explore/<branchId>  我的探索
#topics/<topicId>/<roundId>/review             已公开方案比较
#topics/<topicId>/<roundId>/decision           决策与下一步
```

刷新、复制地址、浏览器后退都能恢复对应页面。直接打开未获准的课题返回无权查看/不存在，不通过切换前端标签绕过权限。新建探索会话后记录稳定地址；尚未创建的输入草稿按账号 + 课题 + 轮次隔离。

将现有 View 与路由解析收敛到 `shared/routes.ts`，使用区分普通会话和课题页面的类型；Sidebar 只消费路由，不让 App 继续从 UI 组件导入整个导航模型。沿用当前 Hash 机制即可，无需先安装 React Router。

## 六个关键界面与动作

### 1. 课题列表与发起

使用现有内容页的行式列表：名称、阶段、我的状态、截止时间、参与人数。没有课题时解释用途并提供“发起课题”，不展示预置故事或假进度。

发起表单首先只展示题目、希望得到的结果、参与者、截止；“补充约束与比较维度”可展开。默认自己为主持人。参与者是现有真实成员，选中成员不代表允许发送站外邀请。点“保存草稿”不启动轮次；点“开始探索”才固定共同简报版本并开放参与。

### 2. 独立探索

```text
40px 顶栏：工作空间 / 课题名称             [上下文] [设置]
228px 主导航 | 课题标题  独立探索  截止时间                    | 资料面板（可收起）
             | 概览 · 我的探索 · 方案比较 · 决策               | 本轮共同简报 v1
             | 仅自己可见；提交版本将在收束时公开               | 本次可用资料
             | 当前方向 [切换探索会话] [+ 新方向]               | 证据来源
             |                                                |
             | 复用聊天消息与输入区                            |
             | [整理成方案]                    [查看我的提交]   |
```

私有范围提示紧邻会话标题，不能只放在默认收起的右栏。我的探索允许多个方向会话，每个会话独立历史；原有全局“新的协作”和快捷键仍打开普通工作台，课题内另有明确的“新方向”。

成员可继续研究、停止生成、失败后重试。其他成员和主持人只看到探索/已提交状态，不看到草稿标题、提示词、调用次数或实时屏幕。进度不用于评价个人绩效。

### 3. 整理与提交方案

“整理成方案”使用当前会话中本人选择的内容生成可编辑草稿。首版可手填并复用现有 Markdown 输入，AI 辅助失败不妨碍提交。表单包括：方案名称、核心主张、证据、限制/风险、建议下一步。方案中的多项主张允许“不确定”或“尚未验证”。

预览明确显示作者、将公开的正文/证据、接收者与公开时点。默认不包含完整探索会话；正文提及其他私有附件时，不将链接自动转换为可公开下载。

点击“提交本轮”保存不可变快照，页面提示“已提交 v1，等待统一公开”。个人探索可继续，后续编辑不会覆盖 v1；公开前可“替换提交”形成 v2，或撤回待公开版本。提交后因刷新失败不能提示“提交失败”并诱导重复提交。

### 4. 主持人公开方案

概览显示“已提交 2 / 3”，按钮是“公开已提交方案”。预览显示提交数量、缺交者、公开范围与后果，主持人可延期或按已有提交推进。未交者的私人过程不在此操作范围内。

公开必须一次性固定方案版本集合。成员早交不早公开，批量公开期间不能有部分成员先看到一半方案。服务端确认后进入“方案比较”；若别人已先推进阶段，刷新并显示当前结果，不再执行第二次公开。

第一版不因截止时间自动公开；截止只提示到期。需要定时公开时应在发起时明确取得成员对公开时点的同意并另外验收。

### 5. 比较与讨论

桌面默认选择两个方案并排比较，更多方案通过列表选择；不是一口气排出十列。比较维度沿用共同简报；侧边可查看原文与证据，AI 的概括不能替代原始提交。

支持“请 Agent 比较”“记录疑问”“采用这个方案”“组合方案”。比较 Agent 的回答标记为分析，缺证据与冲突单列，不自动评分排序或宣布获胜。第一版各成员可有自己的比较问答会话，候选与最终决策共享；多人实时共写聊天作为后续能力，避免先重写现有双人会话权限。

### 6. 决策与接入执行

决策者选择采用/组合的方案版本，填写理由、遗留问题与任务建议。点击“确认决策”后生成版本化决策包；界面明确“结论已确认，以下任务等待承接”。

第一版复用现有找本人主链路：针对每项任务建议，由人选择成员、预览相关决策材料、明确转交；对方通过已有 confirm 接口确认承担并生成待办。决策确认本身不直接调用旧 confirm、不自动代所有人接任务。

创建交接时只携带已公开且接收者可见的决策摘录；不可引用私人探索历史。若接手成员不在课题参与者内，需有权分享该决策包的人明确扩大对应材料的范围，界面单独预览，不用任务创建绕过分享权。

## 拖动、按钮与错误反馈

拖动只是“提交方案”的快捷触发，最终复用同一个 SubmissionEditor 和提交命令。拖动方案卡或探索会话时，只携带服务端对象 ID，由后端重新读取归属；不信任拖放 payload 中的 owner、正文、共享权限或阶段。

- 个人列表排序只改显示顺序，支持撤销，不触发共享。
- 拖方案到提交区，打开该方案的预览；拖整个会话则先整理方案，原会话留在原处。
- 放到无权操作或已关闭的轮次时，显示原因并保留原对象；不做“先移走再请求”的乐观更新。
- 提交按钮、键盘路径、触屏操作始终可用；拖动不是唯一入口。
- 公开前的撤回可恢复编辑；已公开内容只能记录撤回和后续影响，不能承诺别人忘掉它。

输入法、Enter / Shift+Enter、停止重试、向上阅读不强制滚底等行为沿用现有 Composer / Conversation。轮询只更新服务端快照，不覆盖正在编辑的方案；编辑稿单独管理并标记基于哪个服务端版本。

移动端保留课题阶段和可见范围说明；比较改为方案切换/逐项对照，资料从按钮打开。沿用现有 760px 导航抽屉及 768～1020px 上下文规则，新样式限定在 `.topic-*`，复用 Tutti 语义变量，不全局改变现有工作台。

```text
  shared/chat/ChatPanel.tsx               中立消息展示、滚动、复制、来源、运行状态
  features/workspace/Conversation.tsx     保留普通协作的业务包装
  features/workspace/Composer.tsx         可配置资料和可见范围的输入组件
  features/topics/
    types.ts / api.ts / useTopic.ts        契约、命令、当前页面数据与刷新
    TopicList.tsx / TopicPage.tsx          入口与页面组合
    TopicOverview.tsx                    简报、参与者进度、阶段动作
    ExplorationPane.tsx                  本人会话与方案入口
    SubmissionEditor.tsx                 草稿、来源选择、公开预览、提交
    ReviewBoard.tsx                      候选比较与本人分析会话
    DecisionPanel.tsx                    决策包和交接建议
    TopicContextPanel.tsx / topics.css    课题资料与局部样式
```

这些是建议新增位置，不表示文件已经存在。避免给 Conversation 叠加大量 isTopic / isReview / isHost 开关；ChatPanel 只负责展示，角色与业务动作由外层包装提供。新版 Composer 接收 availableSources、scopeLabel、onSend 等明确参数，草稿 key 包含账号、轮次、会话，来源选择也须按同样范围保存和清理。

`useTopic` 使用当前 1 秒轮询机制，页面隐藏时暂停；切换课题取消旧请求并核对响应的 topic/round ID；过期响应不能污染新页面。保存操作单独持有 pending 状态，允许滚动阅读和切换来源；禁止重复执行的是同一动作，不是整个应用。

`command` 现有的操作 ID 缓存在内存，适合短时重试；方案提交、公开、决策需要将待确认命令及 ID 按账号/对象保存在会话级恢复记录中，刷新后可以查询结果。数据应最小化、退出账号清理；恢复不能在用户不知情时创建新的付费模型任务。

## 后端对象、状态与接口

新增 `accord_api/topics/`，建议含 `router.py`、`service.py`、`repository.py`、`schemas.py`、`policy.py` 和版本化迁移文件。将现有 operate 的事务和幂等逻辑提取到 `commands.py`，现有接口与新 Router 共同使用；topics 不反向导入 app.py，避免循环初始化。

| 新表 | 主要约束 |
| --- | --- |
| accord_topics / accord_rounds / accord_round_members | 主持人、简报版本、阶段、截止、参与者和 optimistic version；成员只有已加入轮次才可读取 |
| accord_explorations | round_id、owner_id、thread_id、草稿与草稿版本；一个方向关联一个私人会话 |
| accord_proposal_versions | 提交正文快照、作者、证据版本与允许接收者；版本不可原地修改 |
| accord_submissions | 每成员每轮一个有效提交，引用已选 proposal_version；替换/撤回留历史 |
| accord_releases / accord_release_items | 固定本次公开的方案版本集合；同一轮首版只允许一次公开 |
| accord_decision_packages | 决策内容、采用版本、理由、遗留问题、确认人、版本 |
| accord_thread_scopes / accord_run_inputs | 会话用途与对象关联；本次运行获准的输入版本、历史截止与上下文范围 |

实施时可合并关系简单的表，但保留作者、版本、公开记录与权限判断。使用新增表和有版本号的迁移，不依赖启动时清空数据。

首版将可操作阶段压缩为 draft → exploring → reviewing → decided；“收集中”体现为探索阶段的提交进度，“执行中”由交接任务状态体现。它是设计文档完整状态模型的首版取舍，不会把任务完成混成轮次完成。取消/新一轮另保留明确命令，不允许客户端任意写 status。

| 接口（建议） | 权限与状态 | 页面响应 |
| --- | --- | --- |
| GET /api/topics；GET /api/rounds/{id} | 只返回本人参与课题；含可执行动作与进度投影 | 列表/概览，不含他人草稿或待公开标题 |
| POST /api/topics；POST /api/rounds/{id}/start | 发起人/主持人；简报与参与者完整 | 固定简报版本，进入探索 |
| POST /api/rounds/{id}/explorations | 本轮成员，exploring | 创建本人私人会话，返回课题路由 |
| POST /api/explorations/{id}/draft | 本人，校验草稿 expected_version | 保存草稿；冲突保留本地内容供选择 |
| POST /api/rounds/{id}/submit 或 /withdraw | 本轮成员；本人内容；exploring | 提交/撤回当前有效方案版本 |
| POST /api/rounds/{id}/release | 主持人；exploring；校验轮次版本与提交集合 | 原子公开；返回 release_id 与固定版本列表 |
| GET /api/rounds/{id}/proposals | 本轮成员且 reviewing/decided | 仅返回已公开版本，含来源与撤回标记 |
| POST /api/rounds/{id}/decision | 明确决策者；reviewing | 保存决策包，任务建议保持待承接 |

写操作使用 operation_id + expected_version；相同 ID 和请求体重试返回同一结果，不同内容复用 ID 返回冲突。403/404 表示无权限或不可见，409 表示阶段/版本变化，422 表示字段问题，429 表示实际调用额度；前端按原因提供下一步。

release 的事务需要固定有效 submissions 并写 release_items、阶段和版本。若提交与公开并发，以获得事务并成功校验版本的一方为准；迟到提交明确返回轮次已收束并保留草稿，不悄悄遗漏或混入。

## 上下文隔离必须贯穿旧入口

只给新 Router 加权限不够。以下旧入口都需要识别会话绑定的 scope：`GET /threads/{id}`、发送消息、停止/重试生成、state 的最近会话列表及资料引用。绑定课题的私人会话不能通过普通 handoff 变成整段对外共享；用户需要分享时转到方案提交。

目前 runtime.execute_run 会从共享 artifacts 读取资料，agent.context_messages 再按关键词选取。新增一个 `context.py`，先根据服务端记录的会话/运行用途决定资料范围：

```text
普通协作：沿用现有获准共享资料与当前会话历史
独立探索：共同简报的固定版本 + 本人选定且可用的资料 + 本分支历史
整理方案：本人明确选取的内容，输出保存为私人草稿
方案比较：本轮已公开方案版本 + 获准证据 + 本人的比较问答历史
```

`purpose` 由服务端会话关联推导，不能信任请求者填“我是主持人”或“这是 review”。空 source_ids 代表在该用途允许的范围内检索，不回退到整个 artifacts。

首次汇总创建新会话，不能把某个私人会话改个 owner 或 project 后继续使用旧历史。输入的文档版本与消息截止点记录在 run_inputs 中；重试默认沿用原输入版本，但重新检查当前访问权。授权失效就拒绝，不因为保留了历史快照而放行。

在单工作空间内部，已有共享 artifacts 暂保持原含义，新增未公开内容使用独立存储。以后发布到全团队资料池是另一次明确动作，不能将“对课题成员公开”等同于“对整个工作空间公开”。

## 实施顺序与验收交付

| 批次 | 实际修改 | 完成标准 |
| --- | --- | --- |
| A：可独立探索 | 表迁移、授权/上下文函数、课题入口和个人探索；复用模型队列 | A/B/C 身份下不可互读草稿；刷新可恢复；旧找同事流程保持 |
| B：可提交与收束 | 提交编辑器、快照、统一公开事务、比较页面与决策包 | 双人各提交一案，主持人公开后可比较；重试不重复，决策不代人承接 |
| C：交接与操作效率 | 决策转为现有协作请求、角色状态反馈、拖动与移动端补齐 | 可由责任人明确承接并完成；按钮和拖动语义一致，私有会话保留 |

第一条端到端路径必须有实际账号、实际模型和持久数据。模型故障时允许人手工提交与比较，不用假 AI 内容补成功画面。课题创建和发布只由真实使用者在产品里操作，开发验证使用隔离测试数据。

后端增加 `tests/test_topics.py`：覆盖未提交隔离、早交不早公开、主持人权限、成员范围、旧接口绕过、来源伪造、空 sources 不扩权、提交/公开并发、版本冲突、重复命令、撤回、重启恢复、任务本人确认。模型输入测试拦截传给 provider 的 messages，断言未公开内容确实没有进入，而不只断言响应里没有字符串。

前端验收覆盖：创建真实空课题、两个账号独立探索、方案预览、公开后的比较、第三身份拒绝、刷新/前进后退、轮询不覆盖编辑稿、中文输入法、停止与失败重试、复制来源、键盘和触屏替代操作、390/768/1440 宽度以及亮暗主题。拖动支持在 B 跑通之后验收。

实施后的命令仍使用仓库现有 typecheck、build、check:ui 与 Python unittest；本轮没有改应用代码，未执行功能测试，也不将本计划中的项目标记为已完成。
