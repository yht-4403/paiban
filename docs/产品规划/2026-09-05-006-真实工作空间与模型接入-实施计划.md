# 真实工作空间与模型接入实施计划

## 目标与当前阶段

JC 要求 Accord 面向实际使用：产品中不出现演示身份、预置故事或伪装成真实能力的内容；UI 继续对标 Tutti，AI 使用已授权的 ChengziCV 服务端模型配置。

场景：参考竞品重构已有产品。目标路由：登录与初始化、工作台、会话、成员、拍板、待办、共享成果、设置。当前阶段：本轮实现与验证完成，团队文档已同步并回读。暂按一个部署对应一个团队工作空间设计，不把当前 SQLite 数据库称为多租户 SaaS。

## 证据与设计方向

- 前版代码位于 `apps/web`、`apps/api`；004 验收记录证明的是当时的实现，不能代替真实账号与模型调用验收。
- Tutti 公共组件固定 `@tutti-os/ui-system@0.0.427`；参考源码 commit `404a084f7780c475212f80d6563964c4bd7d8324`。参考 [Tutti 仓库](https://github.com/tutti-os/tutti)、`packages/workbench/surface/src/styles/workbench.css` 的 40px 顶栏和面板层次，以及 `packages/agent/gui/agent-gui/agentGuiNode/composer/` 的输入区与运行反馈。
- 本轮沿用 `impeccable-redesign-orchestrator` 的持续计划和 `frontend-design-teardown` 的证据检查方法；Accord 的唯一视觉规则仍是 harness 004。
- 优先修正窗口比例、导航密度、输入框位置、上下文面板与真实状态。去掉大面积口号、伪项目切换和产品导航中的控件展示入口。没有像素对照证据，不声明“达到 95%”。
- ChengziCV 仅参考 provider 配置与服务端调用结构；不读取其用户业务数据，不修改该项目，密钥值不进入本文或 Git。

## 功能缺口与优先级

| 范围 | 修改前的事实 | 本轮处理 / 后续明确范围 |
| --- | --- | --- |
| 账号 | 可直接选择三个合成人物，无真实认证 | 本轮：首次创建工作空间、密码登录、邀请加入、会话撤销；后续：飞书 SSO、账号恢复、成员停用与角色管理 |
| 数据 | 启动注入合成资料和请求 | 本轮：全新空工作空间，旧本地数据保留隔离；内容由实际成员创建 |
| AI | 没有资料命中就不调用；无历史；付费调用在去重之前 | 本轮：真实 provider、授权历史、无资料也可协助、真实用量与错误、调用前去重、持久运行记录与重试 |
| 协作 | 显式转交、本人确认、任务完成已有服务端校验 | 保留并回归；定时送达改为后台触发。后续：拒绝、延期、撤回、重新打开、读回执与通知 |
| 资料 | 只有文本发布与读取 | 本轮补真实空状态；后续：附件、版本、编辑归档、检索索引、来源段落、撤销共享后的历史边界 |
| 任务 | 只有确认产生任务与完成按钮 | 后续：截止日期、优先级、拆分、阻塞原因、执行产物、归档与筛选 |
| 个人 Agent | 仅能读取共享资料，无个人授权上下文 | 后续：私有资料、代答范围、个人指令、记忆确认与删除；不得把“个人 Agent”标签当作能力完成 |
| 会议 | 新版未实现 | 后续：邀请、议程、讨论、逐人确认结论、会后任务与成品共享，参考既有需求而非凭空补全 |
| 部署 | 本机开发服务、SQLite、轮询 | 后续：团队 HTTPS 地址、备份恢复、生产服务、审计与监控、并发容量；当前不宣称公网可用 |
| UI | 组件一致，但应用壳、输入区、上下文和状态行为仍偏离 Tutti | 本轮修正结构与真实状态；后续针对已选 Tutti 截图逐状态比对 |

## 决策与约束

1. 模型只能产出消息，不能写入确认、分工和完成状态；对方的私人资料不能因进入其 Agent 通道而被检索。
2. 不以删除状态提示的方式隐藏假数据；旧数据库不清空，新的实际使用数据库不播种资料。
3. API Key 只存在于本机服务端配置，文件权限限定本人；复用账号会共用上游额度，Accord 的调用记录单独保存，不复制自动轮换 key 池。
4. 每次模型请求使用明确模型、超时、输出上限；不自动反复请求消耗额度。失败可见，由用户重试。
5. 验证账户和资料仅存在于临时测试数据库。实际工作空间由使用者创建，不替 JC 设置密码或预填虚构项目事实。

## UI 对照结果与边界

| 维度 | 本轮调整 | 仍有差距 |
| --- | --- | --- |
| 设计系统 | 保留同一版本公共控件、Lexend、主题变量与图标 | 组件相同不等于工作台行为全部相同 |
| 窗口 | 40px 顶栏、12px 外框、窗口内导航、紧凑分隔与列表 | 未实现 Tutti 桌面窗口管理、Dock、平铺与缩放 |
| 输入 | 16px 容器圆角、底部上下文条、实际模型、可取消引用、圆形发送 | 未实现文件上传、@ 引用、模型切换、工具权限菜单 |
| 会话 | Markdown、真实用量、状态、复制、阅读位置、停止和重试 | 工具轨迹、文件差异、执行预览、多线程分支尚缺 |
| 上下文 | 默认收起、记住偏好；当前会话显示实际引用和参与者 | 尚无拖拽调宽、关联文件定位、对话与工具双面板同步 |
| 真实状态 | 不播种人物和资料；初始化、空态、断连、未配置、恢复均验证 | 多人异地网络、并发容量与浏览器推送还未验证 |

视觉证据采用固定 commit 的源码与仓库截图，Tutti 当前桌面实例未完成同尺寸逐像素比对。因此不承诺还原率数字。下一轮应先选定工作台空态、生成中、工具执行、资料预览四个对应画面，再逐状态验收。

## AI 后续落地顺序

1. 当前：服务端调用千问，传入当前会话的授权历史与选定共享资料；结果只能形成消息。
2. 下一步：增加明确的工具适配层，先接文件读取、资料检索、文档生成等可验证能力；每次运行记录输入、输出、来源和产物。
3. 对外发消息、跨成员取资料、发布文件与变更任务，使用服务端权限与人类确认，不把模型文字作为批准。
4. 再加入多 Agent 委托、隔离工作目录或沙箱、跨工具恢复、工作空间总预算与审计。当前后台生成队列是单进程队列，不能当作上述执行系统。

协议依据：[百炼 OpenAI 兼容 Chat Completions](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)。本轮固定已在 ChengziCV 使用并实际验证的模型，没有追逐新的模型版本或复制 key 轮换池。
