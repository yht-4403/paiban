# Accord 路演叙事与验证

> 2026-09-05。配套 [核心体验与替代方案设计](2026-09-05-005-核心体验与替代方案-设计文档.md)。以下为 PPT 文案和演示编排建议，不是已生成的 PPT 文件。正式时长未知，先准备 3 分钟主讲和可展开的备份页。

## 一句话定位

**Accord 帮助 AI 小队把协作请求推进到有依据的答复、本人确认和明确的下一步。**

“每人一个 Agent”用来解释工作方式，不能代替用户价值。“少打扰、少等待、少掉交接”是待验证目标；没有事件数据前不写节省百分比。

## 七页 PPT：围绕一件事讲完

| 页 | 建议标题 | 画面与口播要点 | 证据要求 |
| --- | --- | --- | --- |
| 1 | 资料能查到了，事情为什么还在等？ | A 要安排前端联调，文档只有昨天的预计时间，仍不知道 B 能否承诺交付。展示一句问题即可 | 标注为示例；若换成真实经历，去除无关私人信息 |
| 2 | 我们自己先用 GPT + 飞书解决了资料同步 | 展示已经完成的文档索引。坦诚承认：整理、共享和知识问答已有好工具 | 使用本轮真实同步成果，不虚构“以前只能手工复制” |
| 3 | 从“查到了”走到“谁确认了” | 一条流程：查依据 → 需要新决定 → 请求本人 → 确认 / 改约 → 落实回执；标出人的动作 | 不把计划当承诺，不把 Agent 建议当本人意见 |
| 4 | 同一个请求，看两个人怎么完成 | A 问登录接口；B 的助手先用授权资料回答；A 请求明早 10 点交付；B 确认后任务落地 | 用实际跑通版本；当前未完成真实模型联调，不能提前称为实测 |
| 5 | 为什么不直接用现有组合？ | 对照 GPT + 飞书、飞书工作流、Tutti VM：都承认其重叠；我们的聚焦是降低具体请求流程的配置与交接成本 | 采用设计文档的官方来源，差异标注“目标 / 待验证” |
| 6 | 能否让人放心依赖，比多一个聊天窗口更重要 | 三项行为证据：只读授权内容；本人确认绑定具体内容；失败后保留决定并可重试 | 修复后的测试才能打勾；原型问题和未测项放备份页 |
| 7 | 接下来验证：团队还要不要自己催？ | 比较获取承诺所需时间、催问次数、接入维护成本；展示真实结果或明确的验证计划 | 无数据就写“下一步验证”，不填示例数字作结果 |

## 三分钟口播骨架

**0:00–0:25，问题。** “一个小队准备交付。资料里写着‘预计明早完成’，但下游成员需要的是：谁能确认、什么时间能接着做。今天很多协调仍发生在一句句追问里。”

**0:25–0:50，承认现有解法。** “我们自己就用 GPT、飞书和协作规则完成了文档同步。所以 Accord 不把知识问答当作独有能力。我们在验证接下来这一段：需要人的新判断时，怎样把请求交给正确的人，再把决定交给执行者。”

**0:50–1:55，演示。** A 查当前状态，看到依据和日期；提出新的交付请求；系统明确需要 B 确认。B 看到问题与影响，确认或改约。A 看到具体承诺和任务写入结果。重点展示双方的变化，少讲菜单和内部 Agent 数量。

**1:55–2:25，产品行为。** “日常事实能查就直接答。需要承诺时，助手不会替本人答应。决定形成后有可见结果，失败也不会悄悄消失。”这段必须与演示版本相符；未实现时改说“我们计划这样验证”。

**2:25–3:00，竞争与验证。** “现有工具也能搭建这些能力。我们要证明的是：一个普通小队能否少配脚本、少追问，把事情推进得更确定。我们会把自己已经使用的组合方案作为对照，而不是假装它不存在。”

## 评委问：这不就是 GPT + 飞书 + harness 吗？

推荐回答：

“这部分判断是对的。整理、共享资料，我们已经用这个组合做到了。Accord 要验证的是，当资料不足以形成新的决定时，跨人的请求能否更低成本地得到本人确认并可靠落实。通用工具能实现这些，我们不主张技术上不可替代；我们需要用更少的配置、追问和维护证明产品价值。如果这些优势没有出现，做成飞书插件或协作模板，比另建一个平台更合理。”

不要回答“GPT 没有记忆”“飞书只是文档”“Tutti 不支持多人”“我们有权限所以独有”。这些描述不准确，也经不起已知竞品能力和 MVP 问题的追问。

## 演示边界与恢复

- 当前已证明的是本地界面、部分流程和文档发布；真实模型、跨设备协作与关键修复以之后的实际验收为准。
- 明确显示 Agent 依据的日期及状态；旧计划不能在演示中被冒充为新承诺。
- 本人确认使用明确按钮即可，不堆叠多轮重复确认；展示确认后的责任人与具体时间。
- 模型超时就显示失败并允许找本人；有录屏时标注为回放，不把它当实时结果。
- 备份页放架构、已测 / 未测清单、来源、复用范围和团队分工。没有确定的分工不填人名凑齐。

## 本轮应先做什么

1. 用队内真实事例验证“资料可查后仍卡在本人决定”的需求，替换或确认当前假设场景。
2. 修复 MVP 已确认的权限、状态和时区问题；只增加演示所必需的本人确认与回执。
3. 用同类请求比较现有组合和 Accord，总成本包括配置与人工维护。
4. 根据实际结果制作 PPT：有优势就展示证据；没有优势就诚实收敛为模板 / 插件方案。
