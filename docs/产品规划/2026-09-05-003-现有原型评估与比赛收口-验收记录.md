## 判断

团队已有能启动、带持久化和完整页面的 MVP。Accord 当前卡在**协作边界和演示可靠性尚未落实**，同时正式仓库还没有接入这份应用代码。继续现有 FastAPI + SQLite + 原生 JavaScript 最贴近剩余时间；此时迁入 Tutti 的完整桌面和 Go 架构会扩大交付范围。

建议保留一个主故事：A 先问 B 的 Agent → 有依据就回答、来源可查 → 需要决定时由 A 明确找 B → B 回复 → 结论确认后变成记忆或待办。任务、会议和工作池作为这个故事的支撑。技术路线是建议，尚未将参考代码正式导入或修复。

## 静态检查发现，尚未以真实模型验证

- **代答权限依赖提示词。** `engine.py:81` 将对方的私人工作台历史和记忆加入代答上下文；“不要贴出草稿全文”只是提示词约束。应先由服务端选出允许共享的事实，再交给模型回答。此次没有测试真实模型是否泄露草稿。
- **模型输出可以直接触发写操作。** `workspace_send` 消费模型返回的 `edit_file`、`artifact`、`memory`、`close_task_ids`，立即修改工作池、写记忆或完成任务。需要把高影响建议变成待确认对象，由服务端验证明确动作。
- **附件归属校验不足。** `scratch_for_agent(ids)` 缺少所有者参数；下载接口及调用入口需要一并核查，不能只修聊天列表。
- **配置与错误呈现不够可靠。** `llm.py` 把模型名、thinking 和 JSON 参数按特定服务格式发送，超时上限可到 240 秒。Key 未配置时界面仍显示普通助手回答。应该显式显示“未配置 / 调用失败 / 回退”，并把 Demo 请求超时控制在可恢复范围。
- **并发和幂等未验证。** SQLite 单次操作上锁，多个业务步骤没有统一事务；重复确认、断线重发可能带来重复写入。这是需补测项，未声称已复现数据竞争。
- **运行与交付还有缺口。** 依赖只给最低版本，启动脚本偏 Windows；本次可在 macOS 启动，但尚无独立机器安装、真实双机、模型联调和提交包验收证据。
