# Accord 三账号人工路演与固定身份设计

> 目标时间：2026-09-07 现场展示。正式路演取消自动播放与预设结果，改为三个窗口内人工上传、人工输入和人工点击。人物与初始事实可以提前准备；权限、检索、模型回答、会议收集、任务分配、完成判断和用量必须实时发生。体验账号另有一套可主动进入的教学演练，不进入正式演示范围。

## 当前决定

1. Accord 保持为正常可操作的 App。建成、堡天、舒奥不增加“案例播放”“完整流程”或自动点击入口；只有体验者一、体验者二、体验者三提供“演练”入口，帮助操作者学习原有真实流程。
2. 登录页改成六个固定身份，一次点击即可进入，不再要求邮箱、密码、注册或邀请码。
3. 三个演示身份为建成、堡天、舒奥；三个体验身份为体验者一、体验者二、体验者三。
4. 现场同时打开三个窗口，各窗口保存独立身份。操作者按手册手动上传资料、发送问题、发起会前收集、分配任务和勾选待办。
5. 正式演示范围只预置人物、职责和本地素材；体验范围可幂等预置三份共享资料。两种方式都不预置 Agent 回答、来源、会议、推荐结果、任务状态、完成总结或 token。

详细操作见：[三账号现场演示操作手册](../路演案例/2026-09-06-001-三账号现场演示-操作手册.md)；现场复制内容见：[现场输入与点击顺序](../路演案例/2026-09-06-002-现场输入与点击顺序-任务清单.md)；体验账号教学见：[体验账号教学演练设计](2026-09-06-016-体验账号教学演练-设计文档.md)。

## 六个固定身份

| 分组 | 身份 | 稳定 ID | 用途 |
| --- | --- | --- | --- |
| 演示成员 | 建成 | `fixed_demo_jiancheng` | 工程、提问、会议发起与任务分配 |
| 演示成员 | 堡天 | `fixed_demo_baotian` | 产品与路演口径 |
| 演示成员 | 舒奥 | `fixed_demo_shuao` | UI / UX 与任务完成 |
| 体验账号 | 体验者一 | `fixed_trial_1` | 评委或测试人员自由体验 |
| 体验账号 | 体验者二 | `fixed_trial_2` | 评委或测试人员自由体验 |
| 体验账号 | 体验者三 | `fixed_trial_3` | 评委或测试人员自由体验 |

固定身份由服务端白名单提供，前端不能传任意成员 ID 冒充账号。内部可以保留账号表和会话表承接权限、审计和后续迁移，但用户界面不再暴露邮箱或密码。

六个身份在同一服务实例中分成两个隔离协作范围：建成、堡天、舒奥属于演示范围；体验者一、体验者二、体验者三属于体验范围。身份选择页始终展示六个账号，进入某个身份后，成员、资料、会议、任务、会话和 Agent 检索只能读取该身份所在的范围。演示账号的成员列表只显示建成、堡天、舒奥，体验者数据不能进入路演上下文。

每次选择身份后，服务端签发独立会话 token，前端只把它保存在当前标签页的 `sessionStorage` 中，并在请求中使用 Bearer Token。同一个浏览器的三个窗口可以分别保持建成、堡天和舒奥；切换或退出其中一个窗口不会改变其他窗口。

固定身份与此前本地旧账号分属不同成员范围。成员列表、团队资料和 Agent 检索都必须执行同范围校验，避免旧工作区内容混入现场案例。

## 一条真实的现场故事

```mermaid
flowchart LR
    A[三位成员手动上传各自成品] --> B[建成询问堡天 Agent]
    B --> C[Agent 读取堡天共享资料并回答]
    C --> D[建成发起路演决策会准备]
    D --> E[各成员 Agent 汇总真实进展]
    E --> F[系统推荐必要参会人]
    F --> G[建成发起界面复核任务]
    G --> H[Agent 推荐舒奥]
    H --> I[建成人工选择并分配]
    I --> J[舒奥上传完成成果并勾选待办]
    J --> K[AI 查证并生成完成总结]
```

现场只讲三件事：

- **问同事 Agent：**同事已经公开的成果可以直接回答问题，减少打断本人。
- **会前收集：**开会前先确认谁已经完成、谁仍需拍板，只邀请真正需要参加的人。
- **任务分配与完成：**Agent 根据职责和近期成果推荐负责人，人做最终选择；负责人完成后，AI 再检查证据并总结。

待办和工作池贯穿三条链路，不作为单独的大模块讲解。

## 现场资料如何安排

资料位于 `docs/路演案例/现场资料/`：

```text
现场资料/
├── 01-初始共享/
│   ├── 建成-Accord工程进展与验收状态.md
│   ├── 堡天-路演主线与当前进展.md
│   └── 舒奥-工作台交互结论与当前进展.md
├── 02-个人过程-禁止发布/
│   ├── 建成-接口排查临时记录.md
│   ├── 堡天-商业化口径备选草稿.md
│   └── 舒奥-未采用视觉方向记录.md
├── 03-会后纪要/
│   └── 路演最终走查-会后纪要.md
└── 04-任务完成成果/
    ├── 堡天-90秒产品讲稿.md
    └── 舒奥-Accord工作台1440宽度复核结论.md
```

第一组由三位成员在评委面前分别拖入自己的工作池。第二组只用于证明私人工作台内容不会自动向团队开放。第三组保留给后续会议纪要识别能力。第四组只有在任务分配完成后才能上传，避免把未来成果提前变成检索事实。

当前稳定检索格式是 Markdown、文本、CSV、JSON 和常见代码文件。PDF 尚未接入正文解析，因此主演示使用 Markdown；需要打印或投屏时可以另行导出 PDF 备份，但不把 PDF 当作 Agent 已经能够读取的证据。

## 三段人工操作

### 问同事 Agent

1. 堡天在自己的窗口把《堡天-路演主线与当前进展》拖入工作池。
2. 建成进入“找同事”，选择堡天，在同一个聊天框输入准备好的问题。
3. 堡天 Agent 必须完整回答一次，回答完成后展示真实来源。
4. 如果资料足够，现场不点击“找本人”；如果回答不足，仍可在原会话继续找本人。

验收重点是：回答只能引用堡天授权的资料；堡天的私有商业化草稿不能出现在答案或来源中。

### 会前收集

1. 建成打开“开会”，选择决策会，输入“最终走查是否需要三人全部参加”。
2. 选择建成、堡天、舒奥，让三位成员 Agent 分别读取自己的共享进展。
3. 汇总页展示已完成、待确认和未知信息，再给参会推荐与理由。
4. 操作者按真实结果讲解，不为了配合脚本强行改成人工预设答案。

Accord 负责会前准备，不在现场伪装成音视频会议工具。团队可以带简报去飞书或腾讯会议，回来再粘贴会议纪要。

### 任务分配与完成总结

1. 建成输入“完成 Accord 工作台 1440 宽度最终复核”，让 Agent 收集候选成员的职责与近期成果。
2. Agent 推荐 1～3 人；正常证据下舒奥应是第一候选。
3. 建成人工勾选舒奥并分配，舒奥窗口收到真实待办。
4. 舒奥完成后才上传《舒奥-Accord工作台1440宽度复核结论》，再勾选待办。
5. Agent 读取完成证据并总结；证据不足就在原工作台追问，不直接把任务改成完成。

当前稳定能力是一项任务推荐一位最终负责人。整份会议纪要的多任务姓名映射与批量分配仍是后续能力，主演示不把它描述为已经完成。

## 哪些可以提前准备

| 可以提前准备 | 现场必须实时发生 | 不允许出现 |
| --- | --- | --- |
| 六个固定身份、职责、文件和输入文案 | 身份选择、上传、权限检查、检索、模型调用 | 在正式演示账号中自动播放或运行隐藏点击脚本 |
| 三个浏览器窗口和页面布局 | 来源展示、会议收集、候选推荐 | 硬编码 Agent 答案与推荐人 |
| 初始共享资料和私有反证资料 | 任务创建、跨账号可见、完成查证 | 假 token、假 loading、前端直接改成功状态 |
| 任务完成成果文件 | 舒奥在任务分配后上传并勾选 | 提前把完成成果写入工作池 |

评委可以在三个体验账号中自由操作，也可以由体验者一主动进入教学演练。教学层只负责定位、填入练习内容和触发页面原有动作；模型回答、来源、会议收集、任务推荐和完成判断仍使用与主演示相同的真实接口。

## 前端交互要求

- 身份页只有 Accord 标识、“选择身份”、演示成员和体验账号，不出现登录说明长文。
- 点击身份卡立即进入；卡片只显示姓名与对应 Agent。
- 当前账号需要持续显示在左下角或设置入口，三个窗口切换时能立即辨认。
- 设置页主动作改为“切换身份”。切换只清除当前窗口 token。
- 工作台、找同事、开会和分配任务继续使用正常产品入口。正式演示账号不增加路演专属按钮；体验账号可显示“演练”，退出后仍可自由使用所有正常入口。
- 不使用倒计时弹窗。模型耗时时展示真实阶段，失败时停留在原步骤并允许重试。

## 完成标准

- 六个固定身份可以一键进入，接口不返回邮箱、密码或内部占位凭据。
- 同一浏览器至少两个标签页保持不同身份，退出其中一个不影响另一个。
- 固定身份与旧账号的成员和团队资料双向不可见。
- 三位演示成员可以分别上传资料，并在另一个成员的 Agent 问答中按权限被引用。
- 会议收集、任务推荐、任务写入和完成总结都落到真实服务端状态。
- 操作手册逐步写清账号、按钮、输入、预期结果和失败恢复。
- 文档不承诺尚未实现的 PDF 解析、会议纪要批量分配或创建人完成摘要回传。

## 后续实现顺序

1. 完成六固定身份、一键进入、多窗口独立会话和旧数据隔离。
2. 用本地案例资料完整跑一遍三窗口人工演示，记录真实耗时和容易误点的位置。
3. 收紧同事 Agent 的目标成员资料范围，并强制本轮执行上下文工具。
4. 补会议纪要入口、确定性姓名映射、批量任务分配和完成摘要回传。
5. 接入 PDF 正文解析后，再把 PDF 加入正式检索验收。
