# Accord 路演叙事与模拟答辩

> 2026-09-05，北京时间。根据 JC 要求，用 dbs-chatroom、sales-enablement、plain-explainer 组织三位独立子 Agent，完成两轮角色讨论与交叉质疑。角色为虚构投资人、路演教练、普通用户兼黑客松评委，主持人负责事实检查与取舍；这不是实际投资意见、用户访谈或观众测试。本文是可排练的稿件与 PPT 内容方案，未生成 PPTX，也未完成真人彩排。

## 一、这轮确定怎么讲

封面标题：**大家都有 AI，为什么还在等一句话？**

一句话介绍：**同事忙时，AI 先回答共享资料里的问题；需要本人决定，再带着前面的讨论找他，确认后留下双方都能看到的约定。**

收尾：**Accord，把反复解释的时间，还给正在做事的人。**

用同一位同事的两个问题讲出差别：“图片要多大”可以查资料，“今晚八点能不能交”需要本人决定。先证明这一条请求如何处理，不在前三分钟同时铺开会议、多 Agent 执行、团队动态和创新探索。

这套表述不要求宣称技术独有。竞争主张是把跨人交接做成现成流程，并验证普通队友的接入、维护、追问总成本能否更低；目前没有证明领先或付费意愿。

## 二、十句话口播

以下为假设案例，用于讲解；不代表实际客户经历、队友承诺或已经测量的效率。上台时从“想象”开始说，不省略情境标记。

1. 想象明早要发一场活动，你在等图片排版，设计同事正忙着赶图。
2. 你问“图片要多大”，答案早写在文档里，却还是等他停下来再回一遍。
3. 接着你问“今晚八点能交吗”，又得把来龙去脉重新讲一遍。
4. 你在等，他被打断，已经说过的事又说了一遍。
5. 在 Accord，你先问同事的 AI，用已经共享的资料拿到尺寸，就能继续往下做。
6. 但“八点能不能交”，只能由同事自己决定。
7. 你点“找本人”，问题和前面的讨论一起交过去。
8. 他方便时给出答复，确认承担后，双方就能看到同一个约定和待办。
9. 现有工具也能搭出这些动作，我们要把它做成队友直接能用的流程。
10. Accord，把反复解释的时间，还给正在做事的人。

口播提示：第二句重读“早写在文档里”；第四句说完停一秒；第六句放慢，重读“本人决定”；第八句保留“方便时”，不暗示能让忙碌的人立刻回应；第十句看向观众，说完结束，不再追加术语。整段用自己的语速计时，不能把稿件估时当成已彩排结果。

不用的句子：“有了 Accord，你再也不用等同事回复。”它混淆了查资料造成的等待与真人必须花时间作决定。

## 三、三分钟舞台编排

正式路演时长尚未确认，以下是三分钟版本。口播与产品演示交替，避免先念十句再把十句重复演一遍。

| 时间 | 讲什么 / 做什么 | 观众应该看懂什么 |
| --- | --- | --- |
| 0:00–0:35 | 十句稿第 1–4 句；画面上只有两条问题：“图片要多大？”“今晚八点能交吗？” | 同样在问同事，但一个问已有信息，一个需要新决定 |
| 0:35–0:50 | 第 5–6 句，进入实际应用 | 能查的先答，需要本人决定的不能代答应 |
| 0:50–2:10 | 两名演示者完成下面的 80 秒主链路，穿插第 7–8 句 | 问题带着原讨论转交，责任人明确承担，双方状态一致 |
| 2:10–2:40 | 第 9 句，展示替代方案比较及已实现范围 | 现有工具能搭；Accord 选择把这件事做顺，而非宣称独家技术 |
| 2:40–3:00 | 说明下一步验证真实团队能否少追问，再说第 10 句 | 记住要解决的损失，以及接下来如何证明 |

### 80 秒演示脚本

| 时间 | 演示动作 | 口播与注意事项 |
| --- | --- | --- |
| 0–15 秒 | 两名演示者使用各自账号，展示已经允许共享的活动资料 | 先让观众看到尺寸依据；不向实际产品注入虚假人物或数据 |
| 15–35 秒 | A 向 B 的 Agent 输入资料能回答的问题，展示真实生成 | “这一步还没有找本人。”当前读取的是明确共享资料，不是偷偷读 B 的私人对话 |
| 35–50 秒 | A 问新的交付时间，然后主动点击“找本人” | 停顿：“现在，才需要本人决定。”当前不是模型自动升级或自动批准 |
| 50–65 秒 | 切到 B，阅读原讨论，填写结论并明确承担任务 | B 可以在确认前说明自己能做到的时间；不演示尚未验收的承诺后改期功能 |
| 65–80 秒 | 回到 A，展示同一项约定与未完成的待办 | “答应做”和“已经做完”分开；不为追求闭幕效果把未完成工作勾掉 |

80 秒是编排目标，不保证模型速度或真人响应。正式演示前须按真实环境彩排；两端同时在场只能证明操作链路，不能证明日常异步等待缩短。模型超时保留真实运行状态，说明正在等待；若使用提前录制的实际演示，明确标为回放。当前没有验收系统通知推送，不能演成 B 在别的应用自动收到消息。

可选结尾愿景，只用一句且标明下一步：“我们还希望让团队先各自探索，再带着证据一起决定，让各自用 AI 想出来的东西，真正成为共同的行动。”这是 007 的设计方向，不放进当前功能成绩。

## 四、六页 PPT 文案与画面

| 页 | 页面主标题 | 最少页面内容 | 画面建议 |
| --- | --- | --- | --- |
| 1 | 大家都有 AI，为什么还在等一句话？ | “图片要多大？”“今晚八点能交吗？” | 两条大字号问题；不要放架构图和 Agent 数量 |
| 2 | 同一位同事，两个不同的问题 | 已有信息可以查；新的决定要本人来 | 问题分别连接“共享资料”和“本人”；每条线一个动作 |
| 3 | 先查资料，再带着原问题找本人 | 查资料 → 找本人 → 确认承担 → 双方看到约定 | 实际演示为主体；截图只使用真实验收或已获同意的演示内容 |
| 4 | 现有工具能搭，我们要让队友直接用 | GPT + 飞书、Tutti、工作流平台都存在重叠 | 使用第五节的短比较；不画没有根据的竞品全红叉 |
| 5 | 今天能演什么，接下来证明什么 | 本机主链路已有验收；团队净收益仍待验证 | 两栏清晰分开；不把设计稿和真机截图混放 |
| 6 | 把时间还给正在做事的人 | 少一次重复询问，少一次从头解释 | 一句收尾，产品名；需要招募试用时再附经过确认的入口 |

展示“问题”和“人的动作”，不要展示后台规范、Token 数、脚本目录和技术验证流水。答辩需要时，在备份页说明实现、权限与来源。

## 五、与外界竞品的区别怎么说

下面比较的是官方描述的产品重心和我们的选择，不是全功能评测或性能排名。

| 方案 | 已有重叠能力 | Accord 的选择与尚待证明之处 |
| --- | --- | --- |
| GPT + 飞书 + harness | 我们已经实际用这套组合整理、发布、共享文档；ChatGPT Apps 支持连接数据与部分操作 | 将找同事、带上下文转交、本人承担和结果查询做成预置流程；能否比组合少配置、少维护仍待比较 |
| Tutti / Tutti VM | 官方强调人和 Agent 的共享工作环境、实时过程、上下文及产物交接 | 当前聚焦跨人的询问和责任交接；Tutti 同样覆盖协作，不能声称只有 Accord 解决团队问题 |
| Relevance AI 等工作流平台 | 已有 Agent 工作流、人工批准和升级处理 | 不以“我们也有人点确认”为差异；需要证明普通成员能否更容易完成一种具体请求 |

十五秒答法：“现有工具已经能把这些动作搭起来。Accord 把找同事、交代上下文、本人承担和结果查询放进一条现成流程。我们接下来要证明的，是团队少配置、少解释、少催问。”

不能说“GPT 只能聊天”“Tutti 不支持多人”“别人没有人工确认”。也不能用当前规模小来宣称更安全、更可靠或更便宜；没有对照数据就不填比较分数。

## 六、尖锐质疑与可守住的回答

| 质疑 | 现场短答 | 继续追问时怎么接 / 缺什么证据 |
| --- | --- | --- |
| 这不就是 GPT + 飞书吗？ | “很多能力确实重叠，我们自己已经这样用了；现在把跨人交接做成现成流程。” | “能搭出来”和“队友愿意天天用”是两道题；须比较接入、维护、追问和纠错总成本 |
| 你现在有什么别人没有的？ | “目前没有独有能力的证据，今天展示的是一条具体交接流程如何完成。” | 不把功能组合包装成技术壁垒；收益没有出现，就收敛为模板或插件 |
| 群里问一句不就行了？ | “偶尔问一次，用群就够；我们针对反复查资料、催确认的团队。” | 资料总过期或很少重复询问时，先问 AI 可能多绕一步；这类情况不能假装是目标用户 |
| 最后还是要找人，省了什么？ | “省的是已写过的信息再问一次，以及找人后重新解释一遍；本人做决定的时间仍然需要。” | 演示一个资料问题不转交，另一个问题带原讨论转交；真实次数和时间尚需测量 |
| 这不是又多一道审批？ | “普通查资料不要求批准，只有需要本人作新决定或承担任务才找他。” | 当前 A 主动点击找本人，不是系统每句都拦截；检查确认动作是否增加无益步骤 |
| 你的 AI 怎么知道同事最新的想法？ | “它不知道没提供的信息，只能参考已经共享的材料；新决定由本人回答。” | 陈旧或相互矛盾的资料仍是风险；不能用‘每人一个 AI’暗示读到了私人记忆或实时脑内想法 |
| 大家都得换工具、维护资料，值吗？ | “这正是我们要测的成本，不能只算演示里省下的几次点击。” | 对现有组合与 Accord 做相同任务，包含资料维护、错误恢复和入门；目前没有净收益结论 |
| 飞书或 Tutti 加一个功能就能做，你的壁垒呢？ | “当前没有防复制的证据；我们先验证一个高频场景能否被持续使用。” | 可复制不直接等于无价值，但不能拿潜在使用习惯当现成壁垒或付费证据 |
| 你说少开会、提高创新，有数据吗？ | “没有，所以这轮没有把它们当成成绩；独立探索后比较方案是下一步设计。” | 当前不能证明对创新质量的影响；需要有对照的真实过程记录 |
| 你们到底做到了哪一步？ | “已有真实账号、模型、共享资料问答、显式找本人和本人确认任务的本机链路。” | 006 记录已验证范围；公网团队部署、工具执行、多 Agent 委托、探索轮次和完整动态仍未完成 |

遇到技术追问先回答，再给证据；不要用愿景绕开问题。遇到没有验证过的商业问题，说清下一步如何判断，避免每个回答都空泛地说“未来会更好”。

## 七、能讲的事实与边界

以 [006 新版验收记录](2026-09-05-006-真实工作空间与模型接入-验收记录.md) 为当前已验证依据：真实账号与邀请、实际模型、多轮会话、共享资料、后台运行状态、显式转交、本人确认承担与任务完成区分，已有本机检查和行为测试记录。本轮仅复核资料与相关源码，没有重跑整套应用或做新一轮真人演示。

本轮代码复核确认：发起者调用 handoff，接收者本人调用 confirm；确认事务同时写入约定、任务和可见范围。该路径可以防止“模型说答应就改业务状态”，不能据此承诺模型一定答对或完整生产环境安全。

旧 003 的匿名读取、身份写入等问题适用于旧参考副本；新版 006 已记录相关修复，不能继续将其描述为新版已知未修复问题。真实团队使用效果仍未验证，不能报节省比例。

[007 独立探索与集中收束](2026-09-05-007-独立探索与集中收束工作流-设计文档.md)、[008 团队动态和可见权限](2026-09-05-008-团队工作状态与可见权限-设计文档.md)、完整多 Agent 执行均属后续设计。特别不要把 CLI 将文档同步到飞书这件事，讲成 Accord 已接入飞书业务工具。

## 八、两轮聊天室：交锋与主持人裁决

角色持续状态：聊天室仍在进行。后续普通输入沿用这三位角色及本次结论继续；JC 说“结束聊天室”“退出聊天室”或输入 /dbs 时退出。后续需要调用时复用现有子 Agent；不可用则按同样角色与此处记录恢复，不冒充真人专家。

| 角色与判断方法 | 第一轮质疑 | 第二轮修正与保留 |
| --- | --- | --- |
| 投资人：替代成本、购买动机、可证伪主张 | “每人一个 AI”没有证明独有能力；“AI 分身替你工作”暗示尚不存在的执行能力 | 自己也撤回“少等一句回复”的说法，因本人判断仍需等待；支持同一位同事、两个不同问题的可观察演示 |
| 路演教练：具体冲突、一个场景、画面兑现口播 | 希望用“大家都有 AI，为什么还在等一句话”抓住注意；担心只讲规范没有记忆点 | 保留有冲击力的问题，删掉“再也不用等”；保留“他方便时”并用“还给正在做事的人”收尾 |
| 普通用户兼评委：首次理解、额外负担、现场证据 | “问 AI→任务→确认”像聊天加审批；同时讲询问与创新探索，会听成两个产品 | 把“规格”改成“图片要多大”、把“交付承诺”改成“今晚几点能给图”；要求承认低频询问直接发群更合适 |

主持人判断：有效交锋在于“省等待”与“省重复询问”并不相同，“明确承担”与“审批所有动作”也不相同。保留前者可以观察的具体损失，删除无法兑现的总括承诺。三位模拟角色一致，不代表市场已认同。

补充盲区：资料维护本身会花时间；把一次真人确认拆成更多步骤也可能增加成本；模拟的两人同时在线会掩盖异步等待；“有权限才读”不能保证内容新鲜或模型回答正确。上述因素必须进入真实验证，不能只靠漂亮台词消失。

本轮可执行决定：用十句稿开场；演示同一个请求中的查资料与新决定；把真实团队总成本作为下一项证据，暂不把独立探索与全功能协作平台塞进主讲。

## 九、怎样验证小白真的听懂

这是建议验证方法，尚未执行。先找几位没参与项目的人听一次，不提前解释术语、不展示问题答案，然后请其独立回答：

1. Accord 帮谁省掉了什么麻烦？
2. AI 说“预计今晚”，能当成同事答应八点交图吗，为什么？
3. 你上次哪件事愿意用它，或者为什么仍然会直接发群？

记录原话和误解点，不用“觉得不错”当成理解或需求证据。若被复述成“监控同事”“自动替同事答应”“又多一个审批”，先改稿或产品动作。模拟角色的赞同不能代替这些回答。

真实试用时，对比同类请求，交替先用组合方案或 Accord，避免第二次因为记住答案显得更快。记录从提问到有用答案 / 有效约定的时间、接收者实际处理次数、重复解释次数、维护资料的时间和错误事件；区分系统处理、真人等待与人为演示快进。没有完成比较前，不写节省百分比。
