# Accord 三账号现场演示操作手册

> 使用时间：2026-09-07 路演。案例取材于 Accord 当前真实开发过程。账号名称和案例文档是为现场体验准备的数据；检索、模型回答、会议收集、负责人推荐、待办写入和完成总结必须由正式功能实时产生。

## 这次现场只证明什么

1. 同事的问题可以先由对方 Agent 根据已共享成果回答，本人不需要立刻停下工作。
2. 开会前可以先收集每个人的真实进展，只邀请仍需拍板的人。
3. 任务可以根据成员职责与近期成果推荐负责人；负责人提交成果后勾选待办，Agent 再查证并总结。

现场不播放自动流程，不预置 Agent 答案，也不伪造 token、来源或完成状态。操作者在三个浏览器窗口内逐步上传、输入和点击，评委随后可以自由换一个问题继续使用。

## 三个窗口怎么摆

| 窗口 | 账号 | 职责 | 现场用途 |
| --- | --- | --- | --- |
| A，左侧或主投屏 | 建成 | 工程与整体串联 | 提问、发起会前收集、发起任务分配 |
| B，右上 | 堡天 | 产品与路演口径 | 上传产品口径；证明同事 Agent 能回答 |
| C，右下 | 舒奥 | UI / UX | 上传体验结论；接收并完成界面复核待办 |

三个窗口保持登录，不使用邮箱和密码。三个窗口都保持左侧导航展开，通过左下角头像与姓名确认当前账号，防止现场切错身份。

第一组是路演开始时可以放入各自工作池的已知事实。第二组只能进入本人工作台的当前会话，绝不点击“入工作池”。第三组用于复制会后输入。第四组必须等对应任务已经分配后再上传，不能提前放入工作池。

## 开场前检查

这一步在评委到场前完成，不产生案例结果。

- 三个账号都能正常进入同一个工作空间，三个窗口身份正确。
- 身份选择页可以看到六个固定账号；进入任一演示账号后，成员列表只显示建成、堡天、舒奥。体验者一、体验者二、体验者三属于同一实例内另一个隔离协作范围，其资料、会议和待办不能出现在演示窗口。
- 建成、堡天、舒奥三个账号中没有同名的旧资料、旧会议或旧任务。当前界面没有会议和任务的删除入口，完整彩排统一使用体验者一、体验者二、体验者三，演示三账号保持干净；不要在台上修改数据库。
- API 与网页连接正常，模型设置可用；先用测试账号发一句无关问题检查网络，不消耗演示账号的案例状态。
- 三个初始共享文件都小于 16,000 字；任务成果文件尚未上传。
- 浏览器缩放保持 100%，主窗口宽度至少 1280 像素，右侧“待办”和“工作池”完整可见；若右栏被收起，点击顶栏右侧的“待办与工作池”面板图标重新打开。
- 系统通知、聊天软件和密码管理器弹窗关闭；不要在投屏中打开本地账号文件、密钥或数据库。

## 第一段：手动建立真实上下文

预计 45～60 秒。三个文件都由操作者在评委面前上传，说明案例不是写死在网页里的。

| 顺序 | 当前窗口 | 点击与操作 | 预期看到 |
| --- | --- | --- | --- |
| 1 | B · 堡天 | 打开“工作台”，在右侧“工作池”点击“拖入成品”，选择 `堡天-路演主线与当前进展.md` | 提示“已放入 1 份”，列表出现同名资料 |
| 2 | C · 舒奥 | 同样上传 `舒奥-工作台交互结论与当前进展.md` | 舒奥工作池出现资料 |
| 3 | A · 建成 | 同样上传 `建成-Accord工程进展与验收状态.md` | 建成工作池出现资料 |

只出现资料标题即继续，不需要逐份打开朗读。三份文件分别属于各自账号，不能在建成窗口一次上传全部文件。

## 第二段：找同事，先问堡天 Agent

预计 60～90 秒。

1. 在 A 窗口点击左侧“找同事”，选择“堡天”。
2. 确认输入框下方显示“堡天的 Agent”，而不是“发给堡天本人”。
3. 粘贴 [现场输入与点击顺序](2026-09-06-002-现场输入与点击顺序-任务清单.md) 中的“输入一”，按 Enter 发送。
4. 发送后等待真实状态依次变化。界面可能显示“正在连接模型”“正在查阅资料”“正在思考”或“正在生成”，不要口头承诺固定秒数。
5. 回答完成后展开“已查阅”或来源，确认至少能看到 `堡天-路演主线与当前进展`。
6. 这一段不点击“找本人”。向评委指出：堡天窗口没有收到真人接入请求，问题已经由获准资料解决。

### 这段成功的判断

- 回答提到现场应依次展示“先问 Agent、查看来源、必要时再找本人”或意思相同的内容。
- 回答只引用堡天已共享的资料，没有声称读取未公开价格或未拍板商业方案。
- 页面展示的是本次模型真实生成的正文、实际来源和供应商返回后的实际用量；具体措辞可以每次不同。

## 第三段：开会前先收集，不把所有人都拉进来

预计 90～150 秒。只演示会前准备，不在 Accord 中模拟音视频会议。

1. 回到 A 窗口，点击左侧“开会”。
2. 点击“发起会议”，选择“决策会”。
3. 在展开的议题输入框中粘贴“输入二”。输入框占位文字以“写下要讨论的议题”开头；“会议议题与背景”是它的辅助访问名称，不会作为常驻标题显示。
4. “相关成员”保留建成、堡天、舒奥三人，然后点击“让 Agent 收集”。
5. 等待页面显示已收到的 Agent 数量。每份进展都必须真实读取各成员刚才上传的共享资料。
6. 汇总完成后先阅读正文里已经完成、仍待确认和未知的信息，再看界面固定显示的“参会人选”和推荐理由；当前没有三个独立分类面板。
7. 正常证据下，应推荐建成与堡天参加拍板；舒奥的交互规则已经确定，只需异步完成最终 1440 宽度复核，不必参加本轮口径决策。
8. 不为了配合讲稿强行修改模型推荐。如果证据不足或模型给出不同判断，直接展开个人 Agent 回复与来源，说明系统保留真实不确定性。

这段结束在“参会人选”页面。现场口播说明团队可以带着简报去飞书或腾讯会议，Accord 负责会前收集，不替代音视频会议。

## 第四段：根据真实资料推荐任务负责人

预计 90～150 秒。

1. 在 A 窗口点击“分配任务”。
2. 点击右上角“分配任务”。
3. 在展开的任务输入框中粘贴“输入三”。输入框占位文字以“写下要完成的事”开头；“任务目标与背景”是它的辅助访问名称，不会作为常驻标题显示。候选范围保留三人。
4. 点击“让 Agent 收集”，等待三位成员 Agent 返回证据并形成 1～3 位候选。
5. 正常证据下，舒奥应成为第一候选：其共享资料明确记录了工作台交互职责和 1440 宽度验收经验。
6. 系统会预选推荐顺序中的第一位。确认当前只选中“舒奥”；如果不是，点击舒奥将选择切换给他。随后点击“分配给选中成员”。最后选择仍由人完成，模型不能自行派活。
7. 切换到 C 窗口，右上“待办”应出现“完成 Accord 工作台 1440 宽度最终复核”或由输入首行形成的同义标题。

### 为什么不用整份纪要直接批量分配

当前稳定链路是“一项任务 → 推荐 1～3 人 → 人选择一位”。[路演最终走查会后纪要](现场资料/03-会后纪要/路演最终走查-会后纪要.md) 已准备好，可作为后续“从纪要识别多项行动”的产品输入，但现场主链路不把尚未完成的批量分配说成已实现。

## 第五段：舒奥提交成果并勾选待办

预计 60～120 秒。

1. 保持 C 窗口登录舒奥，先把 `舒奥-Accord工作台1440宽度复核结论.md` 拖入右侧“工作池”。
2. 确认出现“已放入 1 份”，再点击刚收到待办左侧的复选框。
3. 系统进入舒奥自己的工作台并显示“正在整理”。Agent 会查阅舒奥获准访问的上下文，寻找已经发生的完成证据。
4. 有证据时，页面出现“已完成……”及一两句真实总结，待办从未完成区移入“今日完成”。
5. 切回 A 窗口，点击“分配任务”，打开刚才的分配记录，再点击“查看任务来源”；任务卡应显示“已完成”。若当前版本尚未向创建人展示完成摘要，只展示舒奥侧的真实完成总结，不口头宣称已自动回传全文。

任务完成前不能提前上传成果文件。否则 Agent 在分配任务时可能把将来的成果误当成既有进展，破坏演示时间线。

## 可选：30 秒权限反证

只有时间充足时再演示。

1. 在 B 窗口进入堡天自己的“工作台”，点击输入框左下附件按钮，选择 `堡天-商业化口径备选草稿.md`。
2. 粘贴“输入四”并发送。附件下方出现“入工作池”时保持不点。
3. 回到 A 窗口与堡天 Agent 的同一聊天，粘贴“输入五”。
4. 正确结果是 Agent 明确表示没有已共享依据，不能给出具体未拍板价格；来源中也没有该草稿。

这个步骤证明“上传给自己的 Agent”和“发布给团队”是两件事。私有文件即使就在堡天的工作台里，也不能自动成为同事可读资料。

## 现场失败怎么恢复

| 现象 | 先做什么 | 恢复动作 | 不要做什么 |
| --- | --- | --- | --- |
| 上传后没看到文件 | 看右侧是否有错误；用搜索查一次标题 | 文件仍不存在时重新选择同一份文件 | 不连续点击造成多个同名副本 |
| Agent 长时间未结束 | 保持当前页，观察具体阶段；检查另外两个窗口是否也在同时生成 | 等当前请求结束；明确失败后点“重新生成”或“重新整理” | 不刷新后口头说已经成功 |
| Agent 没有引用目标资料 | 展开“已查阅”和来源 | 确认文件上传在正确账号、范围为团队工作池，再重试 | 不替模型补一句预制答案 |
| 会议推荐与预期不同 | 展开三位 Agent 回复，核对事实 | 若缺资料，补传正确资料后重新发起一场会议；“重新整理”只会在整理失败或来源失效时出现。事实齐全但结论不同就按真实结果讲 | 不强选不存在依据的人来配合脚本 |
| 任务没有推荐舒奥 | 检查舒奥资料是否上传、候选范围是否包含舒奥 | 若已得到完整推荐结果，补传资料后重新发起一次任务分配；“重新整理”只会在整理失败或来源失效时出现。仍无依据时停止这一段并说明证据不足 | 不用其他账号冒充舒奥承接 |
| 舒奥勾选后被追问 | 说明 Agent 没有把“计划”当成完成 | 先上传成果；在自动打开的同一工作台粘贴并发送“输入六”，Agent 会再次查证 | 不用直接状态接口绕过 AI 查证 |
| 页面刷新或切错账号 | 先看左下/顶部账号名 | 回到对应窗口，从列表打开刚才的会议、任务或聊天 | 不在错误账号重复创建同名事项 |
| 模型或网络明确报错 | 保留真实错误 | 点当前步骤的重试；连续失败则跳到下一条独立功能 | 不播放硬编码答案或把旧截图当实时结果 |

## PDF 怎么处理

当前工作池稳定读取 Markdown、文本、CSV、JSON 和常见代码文件，尚未把 PDF 正文接入模型上下文。现场上传全部使用本目录的 `.md` 文件。

`堡天-路演主线与当前进展.md`、`路演最终走查-会后纪要.md` 和 `舒奥-Accord工作台1440宽度复核结论.md` 适合额外导出成 PDF 作为投屏或打印备份，但 PDF 不参与主演示检索。等 PDF 解析接入并通过权限测试后，再把它纳入 Agent 的真实资料入口。
