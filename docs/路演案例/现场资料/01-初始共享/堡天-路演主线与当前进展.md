# 路演主线与当前进展

负责人：堡天  
更新时间：2026-09-06  
状态：产品主线已拍板，90 秒讲稿待最后收口

## 一句话定位

Accord 是小团队的 AI 协作入口：先让同事的 Agent 根据获准资料回答，再把真正需要判断和承诺的事情交给本人。

## “找同事”这一段的已定演示顺序

1. 建成进入“找同事”，选择堡天。
2. 输入一个与路演方案有关的真实问题，消息默认发给堡天 Agent，而不是直接打断堡天本人。
3. 堡天 Agent 查阅堡天已经发布到工作池的产品口径，完整回答一次。
4. 建成展开来源，确认答案来自堡天共享的成品，而不是模型常识或其他成员资料。
5. 如果 Agent 已解决问题，这一段直接结束；只有答案不足或需要本人拍板时，建成才点击“找本人”。

这段要让评委看到三个事实：问题先被 Agent 承接、答案有来源、本人没有为了重复信息被打断。不要用预置回复，也不要把“找本人”做成自动升级。

## 三段路演的统一故事

- 第一段是问同事：建成向堡天 Agent 询问已经拍板的路演口径。
- 第二段是会前收集：三位成员都提供进展，但只让仍有决策事项的人参加最后走查。
- 第三段是任务推进：根据共享职责推荐舒奥完成 1440 宽度界面复核；舒奥发布成果、勾选待办，Agent 再查证总结。

工作池和待办不单独作为第四、第五个功能介绍。工作池是 Agent 的获准事实来源，待办是会议和任务执行过程中自然出现的状态。

堡天需要参加最后一轮口径决策，因为产品叙事和现场表达仍需拍板。建成需要参加，负责确认真实功能状态与失败恢复。舒奥的核心交互规则已经确定，适合异步完成一轮 1440 宽度检查并接收会后结论，不必为产品口径讨论全程参会。

## 已确认的边界

- 私人工作台和过程附件默认不公开；只有明确发布的成品进入团队工作池。
- Agent 可以说“不知道”，不能用猜测补齐团队事实。
- 任务推荐由 Agent 给出依据，最终负责人由人选择。
- 勾选待办先触发 Agent 查证；没有完成证据就追问，不直接把任务改成完成。
- Accord 负责会前收集和会后执行衔接，不替代音视频会议。
