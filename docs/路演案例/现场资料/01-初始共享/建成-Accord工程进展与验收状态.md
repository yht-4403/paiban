# Accord 工程进展与验收状态

负责人：建成  
更新时间：2026-09-06  
状态：可供团队协作使用

## 当前产品主线

Accord 面向已经在使用 AI 的小团队。每位成员拥有自己的工作台、共享工作池、待办和 Agent。同事先询问 Agent；Agent 只能根据当前接收者有权读取的资料回答。答案不足时，提问者再选择找本人。

本轮现场只验证三个普通产品能力：

1. 同事 Agent 根据目标成员的共享成果回答并展示来源。
2. 会前向相关成员 Agent 收集进展，形成简报和决策会参会建议。
3. 根据职责、成果和状态推荐任务负责人，由发起人选择；负责人提交成果并勾选后，由 Agent 查证和总结。

## 已经完成的工程能力

- 前端使用 React、TypeScript 和 Tutti UI System；后端使用 FastAPI 与 SQLite。
- 真实模型可以检索授权资料、个人会话、待办与会议状态，回答过程展示查阅阶段、来源、耗时和供应商返回的 token 用量。
- 工作台支持把 Markdown 和常见文本文件作为本轮附件；附件不会自动共享，用户点击“入工作池”后才成为团队成果。
- 右侧工作池支持直接拖入文本成品。同一工作空间的其他成员 Agent 可以读取团队共享资料。
- 找同事保持在同一个对话中：Agent 先完整回答，用户需要时再点击“找本人”。
- 同步会、决策会和单任务负责人推荐已经接入真实个人 Agent 收集流程。
- 负责人勾选待办后，个人 Agent 会查阅进展；存在完成证据时总结并完成，证据不足时在原工作台追问。

## 最近验证

截至 2026-09-06，后端自动化检查共 80 项通过；前端类型检查、生产构建和 UI 边界检查通过。隔离账号已经验证过本地文件发布、跨成员读取和重复发布幂等。真实模型调用仍依赖现场网络和服务商可用性。

## 仍需现场拍板

- 三段演示的总时长控制在五分钟左右，模型等待期间由操作者解释当前读取阶段，不承诺固定返回时间。
- 决策会只展示会前资料收集与参会人收敛，不用 Accord 替代飞书或腾讯会议的音视频能力。
- 当前稳定任务路径一次分配一项任务；从整份会议纪要识别并批量分配多项任务仍是后续能力，现场不按已实现介绍。

## 建成当前状态

核心服务和三条链路已经可用。建成仍需参加最终走查，原因是模型网络、账号切换和任务状态需要由工程负责人在现场拍板和兜底。下一步是完成三窗口的完整人工走查，并冻结演示范围。
