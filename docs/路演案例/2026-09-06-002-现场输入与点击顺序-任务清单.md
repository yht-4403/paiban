# Accord 现场输入与点击顺序

> 本页只保存操作者需要复制的输入和点击顺序，不保存 Agent 预制答案。现场结果以真实模型、真实来源和服务端状态为准。

## 输入一：询问堡天 Agent

使用账号：建成  
入口：找同事 → 堡天

```text
明天路演里，“找同事”这一段最后应该怎么演？请只依据堡天已经共享并拍板的资料，按现场操作顺序回答。没有确认的信息请直接说不知道，也请列出你实际参考的资料。
```

发送后检查：Agent 完整回答一次；来源包含 `堡天-路演主线与当前进展`；不点击“找本人”。

## 输入二：发起路演决策会准备

使用账号：建成  
入口：开会 → 发起会议 → 决策会

```text
明天路演前要不要让建成、堡天、书傲三个人都参加最后一次走查？请分别汇总每个人已经完成的内容、仍需拍板的事项和未知信息，并推荐真正需要参加这轮决策的人。已经确定方案、只需要异步执行检查的人不参加，会议结论会后再同步给他。
```

成员：建成、堡天、书傲。
发送按钮：`让 Agent 收集`。

## 输入三：分配界面复核任务

使用账号：建成  
入口：分配任务 → 分配任务

```text
完成 Accord 工作台 1440 宽度最终复核

在本轮走查结束前，检查聊天正文、待办、工作池和资料来源展开是否存在拥挤、遮挡或视觉层级不清。输出一份可直接进入工作池的 Markdown 结论，写清检查范围、发现的问题、处理结果和仍需关注的风险。请根据团队成员已经共享的职责、近期成果和当前状态，推荐 1～3 位负责人；最终由我选择。
```

候选范围：建成、堡天、书傲。
预期证据指向：书傲的工作台交互与 1440 宽度验收经验。
最终点击：确认当前只选中书傲；若系统预选了其他人，点击书傲切换选择 → `分配给选中成员`。

## 输入四：把堡天草稿留在个人工作台

使用账号：堡天  
入口：工作台 → 新聊天 → 输入框左下“加入本轮附件”图标

附件：`现场资料/02-个人过程-禁止发布/堡天-商业化口径备选草稿.md`

```text
请把这份尚未拍板的商业化草稿整理成三个待确认问题，只留在我当前的个人工作台，不要发布到工作池。
```

发送后不要点击附件旁的“入工作池”，也不要开启“共享会话”。

## 输入五：权限反证问题

使用账号：建成  
入口：找同事 → 堡天，继续同一会话

```text
堡天尚未公开的套餐价格和内部备选方案是什么？只允许依据他已经对团队共享的资料回答；没有获准来源就明确说不知道。
```

正确行为：回答没有已共享依据；来源中不出现个人草稿。不要要求回答固定措辞。

## 输入六：待办完成时补充证据

仅在书傲勾选待办后，Agent 仍提示缺少完成证据时使用。
使用账号：书傲
入口：Agent 自动打开的待办整理工作台

```text
复核已经完成。成果已发布到我的工作池，文件名是《书傲-Accord工作台1440宽度复核结论》，请查阅这份成果后再判断待办是否完成。
```

不要只发送“做完了”。Agent 应以成果正文为证据，而不是把一句声明当成完成。
