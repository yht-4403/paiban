# 拍办 UI / UX 设计规范

## 唯一基线

拍办的界面基线是 `@tutti-os/ui-system@0.0.427`，通过 npm 公共包直接接入，精确版本记录于 `package-lock.json`。技术栈为 React 19、TypeScript、Vite 6、Tailwind CSS 4。源码参考 commit 为 `404a084f7780c475212f80d6563964c4bd7d8324`；该 checkout 与 npm 包不是相同版本，不宣称逐文件相同。

本规范适用于拍办。ChengziCV 的品牌色、页面姿态和历史 UI 规则仍归其项目维护。本地 UI Skills 用于分析、实施和验收，不能覆盖这里已选定的视觉基线；不得同时套用多套配色、圆角与组件系统。

## 分层与导入

- 公共控件从 `@tutti-os/ui-system` 导入；图标从其 `/icons` 公共入口导入。先查组件元数据、类型与样板，不复制 shadcn 默认组件或手绘同义图标。
- 样式入口只在 `apps/web/src/styles.css` 引入一次公共 `styles.css`，保留 Tailwind 扫描公共 dist 的 `@source`。
- `features/workspace` 负责协作业务，`features/gallery` 提供组件验收面；`shared/ui.tsx` 只放跨页面组合。Dialog 中文关闭入口由公共 DialogContent、DialogClose 与 Button 组合。
- 业务页面不导入上游内部源码，不修改 node_modules，不反向污染 Tutti 参考 checkout。尚无需要提升到上游公共包的自研组件。

## 视觉规则

| 内容 | 已采用规则 |
| --- | --- |
| 颜色 | 用 `--background-*`、`--text-*`、`--line-*`、`--transparency-*` 等语义变量；拍办可在独立视觉层用 OKLCH 重绑定这些 Token，不在业务组件散落 hex / rgb / hsl 私有色值。主色为冷蓝紫，黄 / 珊瑚 / 紫只做小面积身份与状态火花 |
| 主题 | 根元素 `data-theme="dark"` / `light`；亮色为新用户默认，暗色保留独立三层表面，外观偏好存本机且不被默认值覆盖 |
| 字体 | 沿用上游 Lexend 与系统中文回退；根字号保持 16px，正文 13px，避免破坏以 rem 计算的组件尺寸 |
| 控件 | 默认 Button 实测高 32px、圆角 6px、字号 13px；语义 variant 表达强调度，状态附带文字 |
| 布局 | 40px 顶栏位于窗口内部；桌面 228px 导航、弹性会话区、288px 资料栏。上下文默认收起并记住偏好；768～1020px 隐藏上下文，760px 及以下导航收为抽屉 |
| 间距 | 以 4px 倍数组织面板与内容；图标光学间距、字号和上游组件内部尺寸保持原定义 |
| 容器 | 中性表面、细分隔线、稳定分栏；正文列表按行组织，避免为普通信息增加装饰卡片 |
| 图标 | 沿用 Tutti 图标，icon-only 动作提供中文 aria-label 与 tooltip；拍办图形标识独立，不使用 Tutti 商标 |

### 可信任工具与彩色火花

- 视觉北极星是“可信任协作控制台”：导航面、内容面、上下文面清楚分层，Composer 是工作台首要操作面。
- 单屏高饱和色视觉重量控制在约 10% 以内。冷蓝紫只标记主操作、当前选择和焦点；黄、珊瑚、紫不作为大面积背景，只用于身份、提醒、会议 / 决策和少量空态细节。
- Agent / 真人、权限、资料范围、任务状态和错误必须保留文字或图标说明，不能只靠颜色。
- Logo 只使用双圆互扣的图形标识，不内置中文或英文；旁侧产品名“拍办”与界面文字统一使用 Lexend 与系统中文回退。
- 新增视觉规则集中在 `apps/web/src/visual-theme.css`；业务 CSS 继续使用语义 Token，避免重新形成多套组件系统。

不要用宽泛的 `.header span` / `button > span` 覆盖公共组件后代。业务文本采用明确选择器，Avatar、Badge 等保留自身样式契约。

## 业务交互

1. 找同事先由对方 Agent 接待；本人接入、回复、确认和后续推进保持同一会话、消息流与主输入框。用姓名、Agent 标记和消息中的接续状态说明当前回复者，不要求用户切换 Agent / 真人标签。
2. 检索只读取已明确共享的资料；有来源时显示来源，并区分等待、生成、完成、停止和失败。一般问题可用模型通用知识协助，团队事实仍须有依据。模型未配置时显示实际错误。
3. 找本人时，在原输入框附近展示接收者和将共享的会话范围；补充说明、定时选项与发送就地完成，不再弹出转交窗口。取消后恢复原草稿；接入前未发送的私人草稿不能自动带入真人输入。指定送达时间必须带时区。
4. 由收到请求的本人在原输入框填写结论、确认承担任务，任务名称就地编辑；服务端校验身份和状态，任务卡出现在同一消息流。“本人已回复”与“已确认承担”分开，模型文本不能代替本人动作。
5. 确认任务后仍可在原对话补充信息，Agent 保持暂停代答。任务完成独立于对话和确认；只有责任人明确标记完成，普通回复不能自动完成任务。
6. JC 于 2026-09-06 确认：当前协作事项中，Agent 必须先完整回答至少一次，之后才能找本人；完整表达“不知道”也算回答。生成中、失败、停止及输出截断不算完整回答，不得借历史其他事项的答案解锁。前后端同时校验，保留重试和继续提问入口。
7. 不使用倒计时接受弹窗，不因几秒未点击而自动接受、拒绝或拉人进入聊天。紧急提醒的其他规则仍按后续已确认需求实现。

## 状态与可用性

- 空态说明下一步；请求中禁用重复写入，显示进行中；失败保留明确重试入口。
- Enter 发送，Shift+Enter 换行；中文输入法合成期间 Enter 不发送。
- 弹窗支持 Escape、焦点约束和返回触发器；使用公共组件默认键盘行为。导航、发送和确认不用 hover 作为唯一入口。
- 现场教学演练不使用遮挡内容或锁住页面的聚光蒙版、高亮框；步骤卡片可用鼠标或触控拖动，始终限制在当前视窗内，不影响「退出」与主操作点击。
- 窄屏收起无法展示的上下文按钮；共享资料仍可从“共享成果”进入。
- 尊重 `prefers-reduced-motion`；不新增会干扰阅读的循环动画。
- 当前路演与体验环境使用六个服务端白名单固定身份；选择后通过标签页独立的 Bearer 会话进入，不展示邮箱、密码、注册或邀请码。演示三账号与体验三账号分属两个隔离的协作范围，成员、资料、会话、会议、待办和 Agent 检索不能跨范围出现。预置人物与案例资料必须明确属于现场情境；上游回答、来源、工具调用、任务和成功回执仍需真实产生。浏览器每秒读取运行状态，登录失效后回到身份选择页。

## 验收入口

`npm run typecheck`、`npm run build`、`npm run check:ui`。最后一项检查公共导入、颜色和图标边界，不能代替视觉验收。

浏览器检查暗色、亮色、空态、错误态、弹窗、来源菜单和主要协作路径。检查 390 / 768 / 1440 宽度；视口能力不可用时可用 `tools/viewport-preview.html` 的独立 iframe 验证响应式布局，记录它与真机触控验收的区别。

截图归档到 `screenshots/YYYY-MM-DD-主题/`，组件接入证据见 004；当前真实账号、模型、界面与限制见 006 验收记录。后续任何视觉偏离先更新本规范并说明具体理由。

## 生成与阅读

- 提交被服务端接受后立即清空已发送草稿；后续刷新失败不能伪装为发送失败，避免再次提交相同消息。
- 生成过程有停止动作；失败保留用户消息与已有回答，重试更新原回答。来源和 token 只展示实际收到的信息。
- Markdown 支持列表、表格和代码；不执行 HTML，不自动加载模型给出的远程图片。复制动作有成功或失败反馈。
- 用户向上阅读时不强制滚到底部；有新内容时提供“查看最新消息”。草稿按账号和会话暂存于当前标签页，新建动作清空新的草稿。
- 组件样板只作为开发验收入口，不放入日常产品导航。不添加无法工作的模型选择器、项目切换菜单或在线状态。

## 文案与点击反馈

- 页面标题直接命名内容；删除重复副标题、产品理念、常驻操作教程。空态只给简短状态与可用的下一步。
- 业务动作保留短文字，如「找本人」「承接任务」「分配」。常见图标动作保留中文可访问名称与提示。
- 接收者、可见范围、待处理状态、送达时间和错误必须可见；不要把真实正文当作冗余文案删除。
- 主操作用实色、普通操作用透明或浅底；同级候选同等强调。悬停、按下、选中与键盘焦点明确区分，沿用 Tutti 语义变量。
- 不用满屏彩色按钮或彩色消息边框区分身份；姓名、头像与身份标签承担这项信息。颜色仅辅助表达状态。

## 个人空间与资料栏

- 顶层入口统一“个人空间 / 协作”；不把 Agent 与真人拆成两个聊天窗口。
- 不选资料时普通聊天使用获准目录自动检索；指定文件夹或资料后缩小范围。右侧资料树支持展开、查找、打开和拖入，保留输入草稿。
- 资料可读不等于可向同事转述；范围校验由后端完成。共享文件夹权限与本地同步未上线前不展示假开关。
- 个人普通聊天删除进入回收站，提供撤销与恢复；不以“删除”暗示永久销毁。

## 群聊与消息层级

- 协作列表加号就地选人建群，沿用同一聊天布局；群成员支持右栏查看，窄屏通过标题下人数查看。群主邀请、改名在当前页面完成。
- 普通群消息只发给人；用户显式 @ 一位成员的 Agent 才触发该次模型调用，发送成功后清除目标标签。不要自动让多个 Agent 互相回复。
- 自己的消息靠右，其他人靠左；气泡随内容收窄并限制长文宽度。姓名、时间和系统事件减轻视觉权重；Agent 保留明确身份标签。降低已完成任务的强调，不改变任务状态与业务权限。
- 群聊输入框使用紧凑单行布局，@ 选择保留草稿，标签可移除。正文仍支持换行；图标动作保留可访问名称和键盘焦点。
- 新群不带入私聊，新成员仅可见加入后的消息。资料检索、历史和工具结果必须由服务端按群成员共同可见范围过滤，不以隐藏前端内容代替权限。
- 当前先交付文字群聊与显式 @ Agent；未实现的退群、移出成员、解散、音视频和自动 Agent 协商不展示空按钮。
